## 1. A 3,000-word document

`shell::long_document_tests` (leaf-ui, run with `just acceptance`) types a 3,000-word document into a test window the
way a person would: `##` headings, 60-word paragraphs, bulleted lists nested two deep with Tab and Shift+Tab, to-dos,
quotes, numbered lists and code blocks, all through Markdown shortcuts, Enter, Enter on empty items to leave lists,
Cmd+Enter out of code, and a typo fixed with Backspace in every block. Words include accents, Cyrillic, Japanese and
an emoji. Then it splits and rejoins a paragraph in the middle and types into it. Every block came out exactly as
expected (kind, depth and text), and the saved page reads back the same.

Still to do: writing and editing such a document by hand in the app (mouse selection, drag, paste from other apps).
The Mac's screen was locked for most of this pass.

## 2. Every editor rule has a test

Each row of "Editor behaviour", split into its separate clauses (about 60), was matched to the tests that assert it,
reading each test's body. All were covered except five, now tested:

- moving the caret within a table cell's text, and Up/Down between the lines of a cell with a line break
  (`table/tests/spec_gaps.rs`);
- the second Backspace or Delete next to a table deletes it, and one undo brings it back with its cells;
- Backspace over selected cells empties exactly those cells, in one undo step;
- selected cells copy to other apps as tab-separated rows;
- list numbers are worked out when drawn, not stored (`view/tests.rs`).

## 3. Undo and redo

Every page command (blocks, text, marks, kinds, properties, indent and outdent, moves, splits, merges, duplicates,
tables) is generated by `leaf-model`'s `page_invariants` proptest, and every workspace command by `page_history`. Both
undo everything step by step back to the empty document, comparing the whole state exactly after each step, then
redo everything. This pass added to them:

- a refused or no-op command must leave the page exactly as it was (no half-written change for undo to take back);
- the editor's edited-time stamps, which undo skips on purpose, mixed into the workspace history.

It also added `history/round_trip_tests.rs` (leaf-editor): random sequences of whole editor actions (typing, typing
over a selection, Enter, Backspace, Delete, Tab, Shift+Tab, pasting plain and Markdown text, cut and paste, bold,
turn into, duplicate, delete, move up and down, dragging blocks), each of which may change many blocks. Undoing them
all gives back every earlier page exactly, one step per action, and redo replays them. 3,000 random cases passed.

## 4. Crash recovery

`leaf-store`'s `crash.rs` copies the database files while they are still open (exactly what a killed process leaves)
after edits at random moments with the autosave timer running, and checks every edit older than the autosave delay
(300 ms) survives, in order, with nothing missing in between. It passes.

Still to do: kill the running app with `kill -9` while typing and reopen it.

## 5. 500 pages, six levels deep

`workspace_editor/tree/tests.rs` builds 500 pages six levels deep, all expanded, and lists them: under 50 ms in a debug
build (the sidebar rebuilds this list on every redraw, and a release build is many times faster). The sidebar draws
only the rows on screen (`uniform_list`), so its drawing cost doesn't grow with the page count. `just fixture` can now
make such a workspace to open in the app: `make_workspace <folder> 2026 500 20`.

## 6. Search

`just bench-search` on the 5,000-page, 100,000-block fixture: queries take 16 ms typically, 20 ms at the 95th
percentile, 23 ms at worst over 260 runs (budget: 50 ms). Re-indexing an edited page takes 5 ms at the 95th percentile.
Opening a result at the matching block is `search/tests.rs::full_text_results_open_the_page_at_the_matching_block`.

## 7. Performance budgets

| Budget | Measured | |
|---|---|---|
| Keystroke to paint on a 10,000-block page, < 16 ms | 8.3 ms median, 9.8 ms 95th percentile (one frame of about 200 took 36 ms) | Pass |
| Open a 5,000-block page, < 100 ms | 52 ms median | Pass |
| Cold start to editable, < 500 ms | 550–620 ms on repeat launches, 690–920 ms on the first after a build | **Fail** |

Keystroke to paint comes from the screenshot tool's `bench` mode on a 10,000-block page (real frames, off screen);
opening from `just bench`. Cold start comes from the app itself: `LEAF_STARTUP_TIMING=1 leaf-app <workspace>` prints
the time from launch to the end of the first frame. It is the same with no workspace, a small one, the 5,000-page
fixture or the 10,000-block page, so the time is in starting up, not in Leaf's pages. About 220 ms of it is
gpui-component listing every installed font while it starts. Fixing that needs a change in that library, so it is
its own story, E08-S08 "Cold start under 500 ms".
