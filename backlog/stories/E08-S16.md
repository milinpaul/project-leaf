## Context

The README's CI badge shows the newest finished run on `main`. All `main` runs share one concurrency group, so when
merges come close together GitHub keeps one running and one waiting, and cancels the older waiting run. A cancelled
run shows as "failing" on the badge even though nothing broke (seen 2026-10-31: run 562 cancelled behind #196 while
556 was green on all three OSes). The owner chose to give every `main` push its own run (2026-10-31).

## Acceptance criteria

- [x] `main` pushes each get their own concurrency group (by commit), so none is cancelled or replaced; pull request
      runs still cancel superseded ones
- [x] CLAUDE.md's "check the newest main run" note matches; ADR-073 records the change
- [ ] Workflow still valid (`backlog.py --check`, CI green on the PR)

## Plan

- `.github/workflows/ci.yml`: `group: ci-${{ github.event_name == 'pull_request' && github.ref || github.sha }}`,
  keeping `cancel-in-progress` for pull requests only.
- Update the CLAUDE.md note and add an update to ADR-073.
