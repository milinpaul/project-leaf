## Context

Compute drop targets (before/after/nest) from pointer position over the view model.

## Acceptance criteria

- [x] Drop target computation unit-tested with a fake layout
- [x] Cannot drop a block into its own subtree
- [x] Multi-block drag preserves order
- [x] Tests added; `just check` passes; docs updated if structure changed

## Plan

- New `leaf-editor/src/drag.rs`: `RowBox` (a drawn row's top and bottom), `BlockDrop` (gap and depth: `below`,
  `depth`, `parent`, `after`), `PageEditor::drop_target(dragged, rows, x, y, indent)` and `drop_blocks`.
- Outliner rule: the pointer's y picks the gap (nearer edge of the row), and x picks the depth, clamped between the next
  row's depth and one deeper than the row above (if it can hold children).
- The outline is read without the dragged blocks, so nothing can land inside them; `drop_blocks` also refuses that.
  One `MoveBlocks` keeps order, as one undo step; a no-op drop changes nothing.
- Tests in `drag/tests.rs` with a fake 24 px layout, plus a proptest: every drop lands where its line is.
- Docs: ADR-049, ARCHITECTURE block-handle paragraph, crate doc.
