## Context

Up/down across lines and blocks using a `LineLayout` trait the UI implements.

## Acceptance criteria

- [x] Trait defines line count, x-to-offset, offset-to-x
- [x] Fake layout used in tests
- [x] Moving across blocks keeps preferred x
- [x] Tests added; `just check` passes; docs updated if structure changed

## Plan

- **Trait (`leaf-editor/src/caret/vertical.rs`):** `LineLayout` with `line_count(block)`, `line_of(block, offset)`,
  `offset_to_x(block, offset)` and `x_to_offset(block, line, x)`. Offsets are Unicode scalars like everywhere else;
  x is in page coordinates (shared by all blocks), so nested blocks' indentation is accounted for. `leaf-ui` will
  implement it from GPUI's text layout when the real text element lands (E07-S02).
- **Motion:** `PageEditor::move_vertically(Vertical::Up | Down, &layout)`. Within a block, move to the line above or
  below at the preferred x; at the first/last line, into the previous/next text block's last/first line (dividers and
  images passed over, as with Left/Right). At the top of the page Up goes to the start; at the bottom Down goes to
  the end. The preferred x is remembered across consecutive Up/Down and forgotten on any other caret move.
- **Tests:** a fake monospace layout that wraps at a fixed width, honours newlines, indents by depth and counts a
  grapheme as one column. Tests for wrapping, crossing blocks, keeping x through short lines, skipping dividers,
  page edges, emoji, and resetting x after Left/Right. Docs: ADR 0016 (the layout boundary), ARCHITECTURE note.
