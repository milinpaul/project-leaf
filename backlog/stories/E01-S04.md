## Context

Move pages within and across parents.

## Acceptance criteria

- [x] MovePage to new parent and index
- [x] Moving a page into its own descendant returns an error
- [x] Order preserved after reload
- [x] Unit + property tests
- [x] Tests added; `just check` passes; docs updated if structure changed

## Plan

- `WorkspaceCommand::MovePage { page, new_parent: Option<PageId>, index }`: one commit, validate first.
- Index meaning: the page's **final position** among the new parent's children, counted without the page
  itself. So "move to 0" always makes it first, and moving within the same parent works as drag-and-drop expects.
  Valid range is `0..=len`, where `len` excludes the page.
- Errors: unknown page or parent; `new_parent` is the page itself or one of its descendants (found by walking up
  from `new_parent`; new `MoveIntoOwnSubtree` error); index out of range. Moving to the same place is allowed.
- Tests: unit tests for each case, and order after save and load. A `proptest` property runs random create/move
  sequences, valid and invalid, against a simple reference model: same accept/reject decisions, same order
  under every parent after each step, and the same order again after reload. This also pins down Loro's index
  behaviour.
- `proptest` (already in TECH_STACK.md) added as a dev-dependency of `leaf-model`.
