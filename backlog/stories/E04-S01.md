## Context

Flattened, render-ready view of a page: blocks with depth, list numbering, text runs with marks.

## Acceptance criteria

- [x] View model rebuilt incrementally from Loro change events
- [x] Numbered lists numbered at render time, restart rules tested
- [x] insta snapshot tests for representative pages
- [x] Tests added; `just check` passes; docs updated if structure changed

## Plan

- **`leaf-model`:** `PageDoc` subscribes to Loro's change events and records which blocks each change touched,
  and whether the outline changed (create, move, delete).
  - `take_changes()` hands them over as `BlockId`s; no Loro types leave the model.
- **`leaf-editor/src/view.rs`:** `PageView` is the flattened, render-ready page. Each `BlockRow` has its depth,
  its style with the list number, its plain text and its text runs with marks.
  - **`refresh(doc)`:**
    - re-reads only the touched blocks;
    - if the outline changed or a block changed kind, it re-walks the tree to get the order, depth and
      numbering, reusing the cached text of untouched blocks;
    - otherwise it patches rows in place.
  - `PageEditor::view()` uses it; `rows()` stays as the full rebuild.
- **Numbering** at render time: consecutive numbered siblings count 1, 2, 3. Any other sibling restarts the count.
  Nested lists count on their own, and a numbered item's children don't break its parent's run.
- **Tests:**
  - **Property test:** random commands plus undo and redo; after each step the incremental view equals a fresh
    rebuild, and only touched blocks were re-read.
  - **Numbering:** a unit test per restart rule.
  - **Snapshots:** `insta` for representative pages: nested numbered lists, to-dos, code, marks, an unknown block.
- **The UI** draws from `view()`.
