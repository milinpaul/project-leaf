## Context

The editing rules for a link inside text (ADR 0071): it behaves as one character, and the view model tells the UI
what to draw: the target's current title and icon, or that it is in the trash or deleted.

## Acceptance criteria

- [x] Arrow keys step over a link in one press; Shift+arrows select it whole; Backspace/Delete remove it whole; a selection can't end inside it
- [x] Typing next to a link never becomes part of it; Enter before or after it splits cleanly
- [x] View model: each link as a run with the target's title and icon, and a state (live, in trash, deleted); renaming the target changes the view without touching the page
- [x] Clipboard: rich copy/paste keeps links; plain text writes the title; Markdown writes `[[Title]]`; pasting Markdown `[[Title]]` makes a link when exactly one page has that title
- [x] Search indexes a link as nothing (titles are found by title search); decided in the plan if that changes
- [x] Tests for every rule (PRODUCT_SPEC.md Editor behaviour gains a Page links row); `just check` passes

## Plan

Done together with E10-S04 in one PR (owner's request). A link is already one character in the model, so caret,
selection and delete rules hold by themselves; tests pin them. New `leaf_editor::page_link` (`LinkTarget`, `LinkedText`
mapping page and drawn positions), `WorkspaceEditor::link_target` and `titles_for_links`, clipboard naming
(`Fragment::with_link_names`) and `[[Title]]` paste (`PageEditor::paste_text_linking`), search drops the placeholder.
