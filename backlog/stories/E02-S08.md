## Context

UndoManager per page doc; each step carries cursor/selection for the editor.

## Acceptance criteria

- [x] Every block command undoes and redoes exactly
- [x] Typing merges into one step within the merge interval
- [x] Cursor metadata attached and returned on undo/redo
- [x] Undo round-trip property test
- [x] Tests added; `just check` passes; docs updated if structure changed

## Plan

New module `page_doc/undo.rs`, mirroring the workspace's undo (E01-S06).
- `PageDoc` owns a Loro `UndoManager`, created after load so saved history isn't undoable. It uses the same
  500 ms merge interval (typing groups into one step), and `set_undo_merge_interval` changes it.
- After every undo or redo, the `BlockId ↔ TreeID` index is rebuilt, because Loro re-creates nodes (ADR 0006).
- **Cursor metadata:** `Caret { block, at }` moves from `leaf-editor` into `leaf-model`, and the editor
  re-exports it. The editor tells the page its caret with `set_caret` before each command, undo or redo.
  - Loro's `on_push` hook stores that caret in the step's metadata, as a block ID plus position. Loro's own
    cursors point at TreeIDs that change on undo.
  - `on_pop` hands it back. `undo()`/`redo()` return `History::Done { caret }` or `History::Nothing`.
  - When Loro merges quick commits, it keeps the **first** step's metadata, so undoing a typing burst restores
    the caret from before the burst. For redo, the caret recorded is the one at the moment undo was pressed.
- **Tests:**
  - every block command undoes and redoes exactly (outline by `BlockId`, kinds, formatted text);
  - typing merges within the interval;
  - the caret comes back on undo and redo;
  - loaded history isn't undoable.
- **Property test (invariant 7):** extend `tests/page_invariants.rs`. Record the outline after every accepted
  command, undo step by step matching each outline back to empty, then redo to the end, calling
  `check_invariants()` after every undo and redo.
- **Scope:** wiring Cmd+Z into the editor is E04-S08.
