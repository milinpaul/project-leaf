## Context

Leaf's first network access needs a recorded decision before any code: what is fetched, when, the opt-in, the
safety limits, and which libraries (HTTP client, HTML parser) with a `cargo-deny` check. The owner asked for it
as a spike and named the feature "web bookmarks" rather than links (2026-10-31).

## Acceptance criteria

- [x] ADR covers: opt-in setting and first-time prompt, what is read from a page, limits (schemes, timeouts, size, no private addresses, no JavaScript), where fetching runs and how results reach the document (a command)
- [x] Trial crate (throwaway, branch `spike/E15-S01-trial`) proves the limits against a local test server
- [x] HTTP client and HTML parser chosen with a one-line justification each; `just deny` passes in a trial branch
- [x] PRODUCT_SPEC.md privacy line and TECH_STACK.md updated to allow opt-in previews from Phase 1
- [x] E15 stories updated from the findings and renamed "web bookmark"
- [x] Docs updated; `just check` passes

## Plan

- Trial crate `web-bookmark-spike` on its own branch (never merged): `ureq` 3.5 with a resolver that keeps public
  addresses only, the limits, `html5ever` 0.27's tokenizer reading `<head>`; 8 tests against a local server;
  `cargo deny check` with the extra crates.
- ADR-XXX-E15-S01 (Proposed) with the decision, findings and two open questions (system proxy, "Not now").
- PRODUCT_SPEC (web bookmarks, privacy line, non-goals), TECH_STACK (row, `leaf-fetch` in the crate layout).
- E15 epic and stories: "web bookmark" naming, `web_bookmark` type, limits and command from the ADR.
