## Context

SetBlockKind and SetProp honouring schema rules.

## Acceptance criteria

- [x] Text kept when the target type has text
- [x] Converting to a type without children moves children out to siblings
- [x] Converting to code strips marks
- [x] heading level validated 1..=3
- [x] Tests added; `just check` passes; docs updated if structure changed

## Plan

New module `page_doc/kind_ops.rs`.
- `PageCommand::SetBlockKind { id, kind }`, validated like inserts: no unknown kinds, heading level 1–3. Blocks of an
  unknown kind can't be converted, because that would rewrite them.
- **Text:** kept when the target has text; an empty container is created when converting a divider into a text
  type. Converting to a divider needs empty text: otherwise it's refused (`TextNotAllowed`) rather than losing
  words. The text container is removed so invariant 2 holds.
- **Code:** every mark is stripped from the text, unknown ones included (invariant 5).
- **Children:** converting to a kind that can't hold children moves them out to sit right after the block, in order.
- **Props:** new props are written. Known props the new kind doesn't use are removed (a heading's level when it
  becomes a paragraph); props written by a newer version are kept.
- `PageCommand::SetProp { id, prop: BlockProp }` with a typed `BlockProp` (`Checked`, `HeadingLevel`, `Language`,
  `ImageWidth`, `ImageAlt`), checked against the block's kind (`PropNotForKind`).
- Same kind or value: `Unchanged`.
- Tests: every rule above, plus round trips such as paragraph → heading → code → paragraph.
