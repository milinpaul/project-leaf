## Context

divan benches for the budgets in docs/product/PRODUCT_SPEC.md.

## Acceptance criteria

- [x] Benches for open page, apply keystroke, view model update, save
- [x] Results tracked in CI as an artifact
- [x] Tests added; `just check` passes; docs updated if structure changed

## Plan

- New crate `leaf-bench` (test support, native, like `leaf-fixtures`): a small library with the setup
  the benches share (a big page saved to a scratch workspace folder; an editor with the caret mid-page),
  unit-tested so the coverage gate covers it, and `benches/budgets.rs` using `divan`.
- Benches, at the spec's sizes: open a saved 5,000-block page (load + editor + first view model);
  type one character on a 10,000-block page; type + refresh the view model (keystroke to paint, minus
  drawing); full view-model rebuild for reference; save one keystroke's change to SQLite.
- CI: a `bench` job on pushes to `main` and manual runs (not PRs, to keep them fast) that runs the
  benches and uploads the table as a `bench-results` artifact. `just bench` runs them locally.
- Docs: ADR for the bench crate and the CI artifact; ARCHITECTURE/TECH_STACK crate lists; README index.
- Risk: CI runners are noisy, so the job records numbers but does not fail on budgets; the acceptance
  pass (E08-S03) checks budgets on a real laptop.
