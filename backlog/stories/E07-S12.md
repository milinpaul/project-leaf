## Context

Over the page's text the mouse shows the ordinary arrow, so the page doesn't read as somewhere to type. Like
other editors, the pointer should become the text cursor (I-beam) over block text and the page title. Elsewhere
nothing changes: the cover, images and empty space keep the arrow, and buttons (handle, checkboxes, menus, cover
controls) keep the hand. Asked for by the owner.

## Acceptance criteria

- [ ] The I-beam shows over every block's text (paragraphs, headings, lists, to-dos, quotes, code, image captions) and the page title
- [ ] The cover, images, dividers and the space around blocks keep the arrow
- [ ] Every button and clickable row (sidebar pages and their menus, checkboxes, pickers, dialogs, welcome screen) shows the hand; gpui-component buttons showed the arrow
- [ ] Checked on macOS by the owner (GPUI's test window doesn't report the cursor)
- [ ] Tests added; `just check` passes; docs updated if structure changed

## Plan

- `shell/rich_text.rs`: `.cursor_text()` on the block text element every text row and caption is drawn with.
- `shell/header.rs`: wrap the title input in an element with `.cursor_text()` (gpui-component's `Input` sets none).
- Owner, after the first PR push: buttons should show the hand too. `theme::button` wraps `Button::new` with
  `.cursor_pointer()` and every button uses it (a test scans the crate for stray `Button::new`); other clickable
  rows get `.cursor_pointer()` where they are built.
- No automated test can see the cursor (the test platform keeps it private), so the owner checks it on the Mac;
  the existing UI tests cover that nothing else changed.
