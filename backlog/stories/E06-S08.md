## Context

The spec's "Create or open a workspace (a local directory)" needs the app to remember workspaces. This is the
testable logic behind the welcome screen (E06-S09): a small settings file in the OS app-settings folder.

## Acceptance criteria

- [x] Settings file (JSON) in the platform's app-config folder; unknown fields preserved
- [x] Remembers the last opened workspace and a recent list (most recent first, max 10, no duplicates)
- [x] Missing or moved workspaces are flagged, not silently dropped; "Remove from list" supported
- [x] Corrupt or unreadable settings file → start fresh with a logged warning, never a crash
- [x] Tests added; `just check` passes; docs updated if structure changed

## Plan

- `leaf-store/src/settings/recent.rs`: `recent_workspaces` in `AppSettings` (path + opened time, most recent first,
  max 10, deduplicated by resolved path); `remember_workspace`, `last_workspace`, `recent_workspaces(exists)`
  (flags missing), `forget_workspace`. Unreadable entries skipped.
- `leaf_ui::workspace_root` remembers the workspace on open and saves the settings; `workspace_to_open` picks
  named > last (if present) > default; `leaf-app` uses it.
- Tests: store tests for order, dedupe, cap, missing flag, removal, round trip, bad entries; UI tests for the
  launch choice and remembering on open. ADR-037, ARCHITECTURE.
