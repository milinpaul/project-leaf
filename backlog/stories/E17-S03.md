## Context

In the ⋮⋮ block menu (`shell/block_menu.rs`, `leaf_editor::block_menu`, ADR 0041), hovering "Turn into" doesn't
open the list of kinds; it needs a click. Once open, moving the mouse towards it closes it, so a kind such as
Heading 2 can only be chosen with the keyboard. It should behave like a normal submenu.

## Acceptance criteria

- [x] Hovering "Turn into" opens the kinds list after a short delay; clicking also opens it
- [x] Moving the mouse from "Turn into" into the list (including diagonally across other rows) keeps it open
- [x] Clicking a kind turns the block into it and closes the menu; hovering another row of the main menu closes the list
- [x] Keyboard behaviour unchanged (existing tests still pass)
- [ ] Tests added; `just check` passes; docs updated if structure changed

## Plan

- Cause: `highlight(TurnInto)` only highlights (the list opens on click, and a click toggles it), and with the list
  open, hovering any other main row closes it at once, so a diagonal move to "Heading 2" across Duplicate closes it.
- `leaf_editor::block_menu`: the menu remembers where the pointer is. `highlight` returns a `HoverChange`
  (`OpenKinds` over an enabled "Turn into" with the list closed, `CloseKinds` over another main row with it open)
  and changes nothing else yet; `settle_hover` applies it from where the pointer is *then* (a kind row in between
  keeps the list). `choose(TurnInto)` opens instead of toggling. Unit tests for each.
- `leaf-ui` `shell/block_menu.rs`: on a `HoverChange`, a timer (150 ms open, 300 ms close) calls `settle_hover`.
  Window test: hover opens; a diagonal path through Duplicate into the list keeps it; clicking Heading 2 applies.
- ADR 0041 amended. Keyboard paths untouched; existing tests updated only for the toggle → open change.
