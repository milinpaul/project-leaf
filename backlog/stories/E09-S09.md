## Context

A `database` block that shows a database inside a page, and `/database` to create one. The block points at the database document and holds no data. Deleting the block trashes the database and its row pages with it; undo or restore brings them back (ADR-066 answer 4).

## Acceptance criteria

- [x] `/database` adds an inline database with a title column
- [x] The inline table edits like the full page
- [x] Deleting the block trashes the database and its rows; undo brings them back
- [x] Tests added; `just check` passes

## Plan

Owner answers (2026-10-31): the inline database is listed in the sidebar under its page; copying or duplicating the
block gives a link to the same database.

- Model: `BlockKind::Database { page }` (type `database`, prop `page`), no text or children, never converted; repaired
  to a paragraph without its page; duplicating it gives a paragraph with a page link.
- Editor: `/database` request; `PageEditor::insert_inline_database`; `WorkspaceEditor::make_requested_database` and
  `sync_inline_databases` (trash and restore follow the block, outside the workspace's undo); copy gives a link.
- UI: one view per database shown, the active one taking the table actions; `database_page/inline.rs` draws title,
  bar, table and New, with the page's keys bound to nothing inside.
- Tests: model, editor and workspace unit tests; window tests. ADR-XXX-E09-S09, ARCHITECTURE, BLOCK_MODEL, spec.
