## Context

Dragging a selection across blocks stops at the edge of the visible area: blocks below (or above) can only be
selected if they're already on screen, because the page doesn't scroll while selecting. Dragging the mouse near or
past the top or bottom edge should scroll the page and keep extending the selection. Drag-to-move blocks
(`shell/block_drag`) may need the same.

## Acceptance criteria

- [x] Dragging a selection near or past the bottom/top edge scrolls the page, faster the further out the mouse is
- [x] The selection keeps growing to the block under the mouse while it scrolls, even if the mouse doesn't move
- [x] Scrolling stops when the mouse button is released or comes back inside
- [x] Dragging a block to move it scrolls the same way
- [x] Shift+Arrow selection already keeps the focus block in view (check, and fix if not)
- [x] Tests added; `just check` passes; docs updated if structure changed

## Plan

- Dragging blocks by the handle already scrolls at the edges (`block_drag`, with tests). Text selection doesn't:
  `on_text_drag` only hears moves over a block's text.
- `shell/select_scroll.rs`: a window-wide pointer listener (registered each frame from the page) follows a text
  drag; near or past the list's top/bottom edge it runs a tick task like `block_drag`'s that scrolls and extends the
  selection to the row under the pointer clamped into the view (`DrawnRows` + `PaintedLayout::offset_at`). Button
  up, or the pointer back inside, stops it.
- `block_drag::scroll_speed`: past the edge the speed keeps growing (to 3× at 2 edge-widths out) instead of capping,
  for both block and text drags.
- Shift+Arrow selection: check it already keeps the focus block in view; window test.
