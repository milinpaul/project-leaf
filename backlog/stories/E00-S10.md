## Context

The owner asked (2026-10-30) for the web board to show the project's phases and their progress. Selecting a phase
should show the epics and stories in it, and from the live board the owner should be able to move an epic to
another phase (for example bring a Phase 1 epic forward into Phase 0). Stories follow their epic; moving single
stories is out of scope.

## Acceptance criteria

- [x] The board shows each phase with its name, epic count and story progress, and marks the current phase
- [x] Selecting a phase narrows the epics, the epic filter and the story columns to that phase
- [x] On the live board (`backlog.py serve`), each epic can be moved to another phase; the epic's file is updated
- [x] Story cards, the story drawer and epic tiles show which phase they belong to (owner request)
- [x] Only the board's own page can make that change (no other website can post to the local server)
- [x] `backlog.py phase <epic> <n>` does the same from the command line
- [x] Tests added; `just check` passes; docs updated if structure changed

## Plan

- `scripts/backlog.py`: phase names (`PHASES`, from PRODUCT_SPEC), validate each epic's `phase:`, add a
  `phases` summary to the board data (epics, story progress, current = first with unfinished stories),
  `set_epic_phase` + `phase <epic> <n>` command, and `POST /epic-phase` on the live server, accepted only
  with the board's own Origin and a JSON body (so other sites can't post to it).
- `scripts/board_template.html`: phase cards with progress; picking one narrows epics, the epic filter and the
  columns; epic tiles show all epics (even without stories) with a phase label and, live, a "Move to" menu;
  story cards and the drawer get a phase label.
- Tests: `scripts/test_backlog_phases.py` (phases data, the command, bad input, the server's checks).
- Docs: backlog README and the backlog skill's command list.
