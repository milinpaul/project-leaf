## Context

Found by the Phase 0 acceptance pass (E08-S03). The spec's budget is "cold start to editable: < 500 ms". Measured on
an M1 Pro with the release build (`LEAF_STARTUP_TIMING=1`), launch to the first frame drawn takes 550–620 ms on
repeat launches (690–920 ms on the first launch after a build), the same with no workspace, a small one, the
5,000-page fixture or a 10,000-block page: the time is in starting up, not in Leaf's pages.

Where it goes (a temporary timing build, small workspace):

| Phase | ms |
|---|---|
| process start → GPUI app running | ~100 |
| `gpui_component::init` | ~250, of which 221 is `theme::init` listing every installed font (`all_font_names`, 237 fonts) to resolve `.SystemUIFont` and the monospace default |
| Leaf's settings, theme, fonts | ~1 |
| opening the window | ~100 |
| building the shell | ~5 |
| first frame | ~85–100 |

Without the font listing the rest is about 330 ms, under budget. gpui-component 0.8.1 is the newest release, and
the listing happens inside its `init` before Leaf can set its own fonts, so the fix needs a change in the library
(skip the listing when the theme's fonts will be replaced, do it lazily, or on a background thread): a small
upstream patch or a `[patch]` to a fork, with an ADR.

## Acceptance criteria

- [x] Launch to first frame under 500 ms on repeat launches of the release build on this Mac (`LEAF_STARTUP_TIMING`): 337, 455 and 318 ms (owner, 2026-10-31)
- [x] The UI and code fonts are still Leaf's own (Inter, and a bundled code font the owner approved from screenshots on 2026-10-31)
- [x] Decision recorded in an ADR; `just deny` passes if a fork is used
- [x] Tests added where possible; `just check` passes

## Plan

- Owner's choice (2026-10-31): bundle a code font rather than patch or fork gpui-component.
- Bundle JetBrains Mono NL (Regular, Bold; OFL; no ligatures) next to Inter; `CODE_FONT` in `theme.rs`, named in
  both theme configs.
- `theme::install` loads the fonts and sets Leaf's theme global **before** `gpui_component::init`, so the library's
  setup sees non-default faces and skips its font listing; `theme::init` keeps applying the appearance.
- Tests: the bundled files hold both families; the library's setup keeps Leaf's faces; both modes use them.
- ADR-077 (and a note in ADR-027). Timing: compare `LEAF_STARTUP_TIMING` before and after on Linux here; the owner
  confirms the < 500 ms on the Mac, and screenshots show the new code font.
