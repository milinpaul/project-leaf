## Context

The owner wants an independent Leaf web app, like Notion on the web, built in Next.js around the WebAssembly build
that the spike (E14-S01) proved; accounts and sync come later (2026-10-31). Before code, one decision record settles
the shape so the next stories don't each re-decide it.

## Acceptance criteria

- [ ] An ADR (`ADR-XXX-E14-S02-...`) records:
  - Next.js (TypeScript, App Router) for the app, and why over a Rust web framework (Leptos, Dioxus)
  - the boundary: the Rust core in WebAssembly owns every editing rule; TypeScript draws view models and forwards
    events (rules 2 and 3 apply to the web as to desktop)
  - where the code lives: a `leaf-web` crate (wasm-bindgen bindings, wasm-ok) and a `web/` app folder, and how they
    sit in TECH_STACK's dependency rules and CI
  - browser storage: IndexedDB with a Loro snapshot plus updates per page and the workspace document, compaction, and
    workspace export and import as a file
  - what the browser can't reuse from desktop and the plan for each: search (SQLite FTS5), images and assets, fonts
  - the download size budget and how it is checked
  - how accounts and the sync server (E14 notes) attach later without changing the stored format
- [ ] TECH_STACK.md and ARCHITECTURE.md describe the web app; `docs/README.md` maps any new folder
- [ ] `just check` passes
