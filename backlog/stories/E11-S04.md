## Context

After autosave writes a page, re-index that page off the UI thread. Rebuild the whole index in the background when
`SearchIndex::open` reports one is needed. The index only reads documents.

## Acceptance criteria

- [x] A page edit is searchable within 1 s of the edit, without blocking typing
- [x] Renaming, trashing, restoring and permanently deleting a page update the index
- [x] Full rebuild runs in the background on open; title search keeps working meanwhile (the quick switcher, E06-S04, searches titles in memory and never touches the index)
- [x] Deleting `search/` while the app is closed loses nothing: it is rebuilt on next open
- [x] An index error is logged and triggers a rebuild; it never blocks editing or saving
- [x] Tests added; `just check` passes; ARCHITECTURE.md data-flow section updated

## Plan

Built together with E11-S03 in one PR (owner's request).

- **Change detection without the UI:** `leaf-store` gains `Store::saved_versions()`: for each document, its
  last save time and the highest update `seq` (strictly increasing, so two saves in the same millisecond still
  differ). The index stores the version it indexed each page at.
- **Reconcile (`sync.rs`, pure, tested with a fake source):** compare saved versions and the workspace's
  searchable pages (titles, trash) with what the index holds; re-index pages whose version or title changed,
  remove pages that are trashed or gone. A rebuild is "clear, then reconcile". Covers rename, trash, restore,
  permanent delete, and edits made before a crash.
- **Source (`source.rs`):** a `PageSource` trait (load workspace, load page, saved versions), so `leaf-search`
  doesn't depend on `leaf-store`. `leaf-ui` implements it over a second `Store` connection.
- **Worker (`worker.rs`):** a background thread owning the index. Opens it, rebuilds if needed, then waits
  for pokes; bursts are merged. The UI pokes after autosave writes something: a channel send, never blocking.
  On any index error it logs, recreates the index file and rebuilds. Dropping the worker stops a rebuild
  between pages (left incomplete, so it reruns next open) but still applies pokes already sent.
- **UI:** `Storage` starts the worker; `Shell::save` pokes it when something was written. No logic in `leaf-ui`
  beyond that.
- **Docs:** ARCHITECTURE.md data flow, ADR 0023.
- **Tests:** reconcile cases, worker end-to-end (edit searchable within 1 s, deleted `search/` rebuilt,
  damaged index recreated), `saved_versions` in leaf-store.
