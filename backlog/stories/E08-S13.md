## Context

Found by a security and code-smell review of the repo tooling (2026-10-31). `SECURITY.md` puts "anything that
lets Leaf read or write outside the workspace folder" in scope. `workspace/folders.rs` already rejects dot-names
and unsafe characters; this story proves, with tests, that no name stored in a workspace file can make Leaf
touch a path outside the folder the user chose.

## Acceptance criteria

- [x] List every place a path is built from stored or user data (assets, page folders, attachments, recent
      workspaces) in the Plan
- [x] Tests that names with `..`, absolute paths, drive letters, UNC paths, Windows device names (`CON`, `NUL`,
      `COM1`), trailing dots/spaces and control characters are rejected or safely renamed
- [x] A symlink inside the workspace that points outside it is not followed for writes
- [x] A proptest: any generated name maps to a path that stays under the workspace root
- [x] Any fix starts with a failing test; `just check` passes

## Plan

Where paths are built from stored or typed data:
- **New workspace names** (`workspace/folders.rs`, `new_workspace_path`): typed by the owner. Already rejects
  separators, `:`, dot-names and control characters; **misses Windows device names** (`CON`, `NUL`, `COM1`,
  `con.leaf`, ...). Add a `NameProblem::Reserved` and reject them.
- **Asset files** (`assets.rs`, `path_of`): `assets/<AssetId>`, where `AssetId` is a typed 32-byte hash shown as
  64 hex characters, never a stored string, so it can't hold `..` or a separator. Prove it with a proptest.
- **Fixed files** (`workspace.sqlite` + `-wal`/`-shm`, `leaf.lock`, `assets/`, `search/`, `search/index.sqlite`,
  the view-state JSON and its `.tmp`): fixed names, but **any of them can be a symlink** in a crafted workspace,
  and Leaf follows it for writes. Owner's decision (2026-10-31): **refuse to open** a workspace whose folder,
  `assets/` or `search/` holds a link; nothing is changed. New `StoreError::LinkInWorkspace`, checked before the
  lock is taken, with a plain-words welcome-screen message. The workspace folder itself may be a link (the owner
  picked it).
- **Recent workspaces** (`settings/recent.rs`): paths the owner opened, from their own settings file; out of scope.

Tests: new `leaf-store/tests/containment.rs` (names table, device names, proptests for names and asset paths,
unix-only symlink cases), `open_problem` message test in leaf-ui. ADR 0074.
