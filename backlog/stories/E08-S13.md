## Context

Found by a security and code-smell review of the repo tooling (2026-10-31). `SECURITY.md` puts "anything that
lets Leaf read or write outside the workspace folder" in scope. `workspace/folders.rs` already rejects dot-names
and unsafe characters; this story proves, with tests, that no name stored in a workspace file can make Leaf
touch a path outside the folder the user chose.

## Acceptance criteria

- [ ] List every place a path is built from stored or user data (assets, page folders, attachments, recent
      workspaces) in the Plan
- [ ] Tests that names with `..`, absolute paths, drive letters, UNC paths, Windows device names (`CON`, `NUL`,
      `COM1`), trailing dots/spaces and control characters are rejected or safely renamed
- [ ] A symlink inside the workspace that points outside it is not followed for writes
- [ ] A proptest: any generated name maps to a path that stays under the workspace root
- [ ] Any fix starts with a failing test; `just check` passes
