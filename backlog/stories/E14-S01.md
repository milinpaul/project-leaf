## Context

The owner asked for an investigation and a spike for the Phase 3 web editor (2026-10-31), ahead of E13. E14's notes
fix the direction: the Rust core (`leaf-model`, `leaf-editor`) in WebAssembly, a hidden text input instead of
`contenteditable`, `leaf-editor` owning the caret and selection, and a Rust sync server (`axum`, Postgres) relaying
Loro updates. The spike checks how much of that already works and what is missing, before any stories are written.

## Acceptance criteria

- [x] A throwaway page (outside the workspace build) runs `leaf-editor` in a browser through WebAssembly: typing,
      Enter, Backspace, Tab, arrows, undo and redo, Markdown shortcuts, rendered from `PageEditor`'s view rows
- [x] Two browser tabs edit the same page at once and converge by exchanging Loro data, with no server
- [x] Measured: WebAssembly download size (raw and compressed), load time and time per keystroke
- [x] A report in `docs/spikes/` with findings, gaps in the core crates, risks (input methods, selection, large
      pages) and a proposed story breakdown for E14 and the sync server; screenshots
- [x] Nothing in the workspace build changes; `just check` passes

## Plan

- `spikes/web-editor/`: its own Cargo workspace (outside the main build) with a `wasm-bindgen` wrapper over one
  `PageEditor`: typed text, named keys, undo and redo, bold and italic; HTML drawn from `view()` rows.
- `web/`: a plain page with a hidden textarea (composition-aware) and sync over a `BroadcastChannel` (snapshots).
- `drive.cjs`: Playwright drives two tabs at once, checks convergence, measures load and keystroke time, takes
  screenshots.
- Report in `docs/spikes/E14-S01-web-editor.md` with gaps, risks and a proposed E14 breakdown.
