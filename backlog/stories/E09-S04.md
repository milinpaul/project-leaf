## Context

A `DatabaseEditor` turning a database into a table view model: visible columns in order with widths, rows sorted and filtered, each cell's display value. The first screen of rows comes first and the rest is read in the background, then kept up to date from Loro's change events (ADR 0066 measurements).

## Acceptance criteria

- [x] View model with columns, rows and display values; `insta` snapshots
- [x] Sort and filter applied in the view model; ties keep row order
- [x] First screen ready without reading every cell; updates after an edit don't re-read the database
- [x] Tests added; `just check` passes

## Plan

- **Model:** `Database::take_changes()` (like `PageDoc::take_changes`, from Loro events): rows whose cells changed,
  whether the row order, the columns or the view changed. So edits, undo, redo and merges are all seen the same way.
  `Database::row_values(row)` reads one row's cells in one go.
- **`leaf-editor/src/database_view.rs` + `database_view/`:** `DatabaseEditor` owns a `Database` and a cache of the cells
  read so far, in stored row order. `read_more(n)` reads the next `n` rows (the UI calls it on idle ticks: "in the
  background" without threads, the crate is wasm-ok); `view(titles, offset)` first applies pending changes (re-reading
  only changed rows) and builds a `TableView`: visible columns (hidden left out) with widths, a title column from the row
  pages, rows filtered and sorted (stable, so ties keep row order; empty values last), each cell as a `CellDisplay`
  converted for its column's current type (ADR 0066 answer 3). With a sort or filter on, the view says it is incomplete
  until every row is read.
- **WorkspaceEditor** keeps `DatabaseEditor`s instead of bare databases; its row actions go through them.
- **Tests:** display conversion per type pair, sort (types, direction, ties, empties), filters (each op, unknown op
  ignored), first screen reads only that many rows, an edit re-reads one row, undo/redo/merge picked up, `insta`
  snapshot of a sample table.
- **Docs:** ARCHITECTURE.md databases paragraph.
