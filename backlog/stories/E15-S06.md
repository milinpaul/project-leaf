## Context

The owner decides whether Leaf may go online for previews. Off by default; the first web bookmark asks once
(ADR-080). The setting belongs to the device (`settings.json`), not the workspace.

## Acceptance criteria

- [x] Settings › Privacy has "Fetch previews for web bookmarks", off by default, with a one-line explanation of what is sent
- [x] The first web bookmark created asks once: Allow / Not now; the answer is saved and "Not now" is never asked again (owner, 2026-10-31)
- [x] With the setting off, no network request is ever made (tested); turning it on fetches missing previews when their page opens; a preview that arrived by sync is never fetched again
- [x] Tests added; `just check` passes; docs updated if structure changed

## Plan

- Editor: `has_preview_requests`, `request_missing_previews` (bookmarks never fetched: no `fetched_at`).
- UI: `shell/previews_question.rs`, a bar at the bottom of the page that asks once when a bookmark wants a preview
  and the setting is unanswered (requests wait); Allow / Not now saved at once. `settings_dialog/privacy.rs`:
  Settings › Privacy with a switch and the same explanation. `settings::observe`: the shell fetches the open
  page's missing previews when previews are turned on; also when a page opens. Fetches no longer need a window.
- Tests: editor (missing previews, a fetched or synced one never again); 3 window tests with a local server (Allow
  fetches the waiting preview; Not now: no request, never asked again; turning on fetches missing, not twice); the
  Privacy switch. Found by the tests: the bar's and the card's text pushed the buttons out of view (fixed).
- Real-world fetch not possible here (no direct DNS; HTTPS intercepted by the sandbox's own CA, which the fetcher
  rightly refuses): to try on the owner's Mac.
- PRODUCT_SPEC rows, ARCHITECTURE, README, SECURITY; screenshots light/dark.
