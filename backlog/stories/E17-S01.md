## Context

The page scrolls in jumps instead of smoothly, unlike a web page. Scrolling happens in the virtual page list
(`crates/leaf-ui/src/shell/page_list.rs`, ADR-035). Find out whether it comes from wheel events being turned
into whole lines, a re-layout that moves the content (rows changing height as they are measured), or redraw cost,
and fix the cause. Check trackpad (pixel deltas, momentum) and mouse wheel (line deltas) on macOS.

## Acceptance criteria

- [x] Trackpad scrolling follows the fingers and coasts with momentum; mouse-wheel scrolling moves evenly
- [x] Content doesn't jump while scrolling through rows that weren't measured yet
- [x] Holds on the 10,000-block fixture page (`just fixture`) within the frame budget
- [x] Cause and fix recorded in the story Log (ADR if the approach changes)
- [x] Tests added; `just check` passes; docs updated if structure changed

## Plan

- Cause: trackpads send pixel deltas, which the list already follows; mouse wheels send line steps, which GPUI's
  list turns into an instant 20 px jump per line, with no glide. Measured frame cost is well inside budget (ADR-035),
  so the jumps, not slow frames, are what feels rough.
- `shell/smooth_scroll.rs`: a capture-phase wheel listener over the page takes line steps (stopping the list's own
  jump), adds 40 px per line (Chrome's step) to a pending distance, and a short task glides it out with an
  exponential ease (time constant 40 ms, done in about 150 ms) using `ListState::scroll_by`. Pixel deltas pass
  through untouched. The ease is a pure `Glide` struct with unit tests; a window test drives it with the test clock.
- Pages under popovers (slash menu, pickers) keep their own wheel: the listener checks its hitbox is hovered.
