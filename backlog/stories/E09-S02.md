## Context

The `Database` model from ADR 0066: one Loro document holding the column tree, schema, row tree, cells and view, changed only through `DatabaseCommand`s (add, rename, retype, move, hide and delete a column; add, move and delete a row; set a cell; set the sort and filters). Text properties are plain text (ADR 0066 answer 2). Unknown property types and keys are kept. Cells of deleted rows and columns stay in place, unread.

## Acceptance criteria

- [x] Commands for columns, rows, cells and the view, each with a test
- [x] Invariants checked after every command (order entries have a schema, IDs unique, values match their column's type or are kept as unknown)
- [x] proptest: random command sequences keep the invariants; two peers converge; undo round-trips
- [x] Unknown property types survive edits from this version
- [x] Tests added; `just check` passes; ARCHITECTURE.md and BLOCK_MODEL.md describe the database document

## Plan

- **IDs** (`leaf-core`): `DatabaseId`, `ColumnId`, `OptionId` (UUID v7 like the others). Rows are `PageId`s.
- **`leaf-model/src/database.rs` + `database/`**, mirroring `Workspace`/`PageDoc`: `Database` owns one Loro doc with
  `"columns"` and `"rows"` flat trees (fractional index; node meta `id`), `"schema"` map (column ID -> map: `name`,
  `type`, `options` mergeable movable list of `{id, name, color}`, `hidden`, `width`, unknown keys kept), `"cells"`
  (row ID -> mergeable map: column ID -> value; multi-select a mergeable map of option ID -> true) and `"view"`
  (`sort` and `filters` as plain values, last writer wins as a whole). Load/save/recover/unsaved changes like pages,
  undo/redo with the index rebuilt from IDs.
- **Types** (`database/property.rs`): `PropertyType` (text, number, select, multi-select, date, checkbox, URL,
  `Unknown(name)`), `CellValue` read by the stored shape (`Text`, `Number`, `Date`, `Checkbox`, `Options`,
  `Unknown`), `SelectOption`, `Column`, `Sort`, `Filter` (unknown filter ops kept as they were).
- **Commands** (`database/command.rs`, `apply.rs`): add, rename, retype, move, hide, set width, delete a column; add,
  rename, recolour, delete a select option; add, move, delete a row; set or clear a cell (checked against the column's
  type and options; unknown-type columns are read-only); set the sort; set the filters. One commit and one undo step
  each; refused commands write nothing.
- **Invariants** (`database/invariants.rs`): column and row IDs valid and unique, every column node has a schema,
  option IDs unique per column, types readable.
- **Tests:** unit tests per command; proptest command sequences (invariants), two-peer convergence and undo
  round-trips (`tests/database_*.rs`); a newer type's column and cells survive. Docs: BLOCK_MODEL.md "Database doc",
  ARCHITECTURE.md, ADR 0066 cross-reference.
- **Risk:** size (L). Keep row pages, storage and UI out (E09-S03+).
