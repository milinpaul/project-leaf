## Context

Found by the `main` CI run on Windows (2026-10-31): the two-peer convergence property test
(`leaf-model/tests/page_convergence.rs`) failed with "due_time is set without a due date". One device clears an
action item's date (which also clears its time) while another sets its time; after merging, the stored props have
a time and no date, and reading the block fails, so the page breaks invariant 4. Introduced by E19-S01 (ADR 0068).

## Acceptance criteria

- [x] A failing test first: two peers, one clears the date while the other sets the time; after merging, both read
      the same valid action item
- [x] Reading an action item ignores a time with no date (the item has no time), keeping the stored value as the
      never-drop-data rule asks; the next change to the item writes a consistent set of props
- [x] The CI failure's case is saved in `page_convergence.proptest-regressions`
- [x] ADR 0068 notes the rule; `just check` passes

## Plan

- Failing test in `leaf-model/src/page_doc/task_tests.rs`: two peers, date cleared on one and time set on the
  other; merged, both read the item with no time, and the next change removes the stray stored time.
- `block_kind.rs` `read_task`: a time with no date reads as `None` instead of an error.
- The old "a valid time with no date is bad data" case leaves the bad-data test; an unreadable time still is.
- Save CI's case in `page_convergence.proptest-regressions`; note it in ADR 0068.
