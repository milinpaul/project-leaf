## Context

The model from ADR 0075: a `"views"` tree for tab order and a `"view_settings"` map for every view but the first,
which stays in `"view"` and the schema so a database saved today, and a device on the older version, keep working.
View commands, each one undo step: add (table or board), rename, set layout, set grouping, move, delete (not the
first), duplicate, and per-view sort, filters, hidden properties, widths, hidden groups and card properties. A layout
or key from a newer version is kept.

## Acceptance criteria

- [ ] A database saved by the previous version reads as one "Table" view, and reading writes nothing
- [ ] Every view command works, is one undo step, and survives save and load
- [ ] The two-device cases from the E22-S01 spike hold as proptests (views, tabs, deletes)
- [ ] Unknown layouts and keys survive this version's edits
- [ ] Tests added; `just check` passes
