## Context

Copying a block and pasting it inside Leaf gives plain text: the block's type (heading, to-do, quote…) and its
formatting are lost. Copy should write Markdown plus Leaf's own fragment as clipboard metadata
(`crates/leaf-ui/src/shell/page_keys.rs` `on_copy` / `clipboard_item`, ADR 0030), and paste should read the
fragment back (`on_paste`, `Fragment::from_json`), falling back to Markdown (ADR 0032).

Things to check, in order:
- Does the metadata survive the macOS pasteboard in our GPUI version (`ClipboardItem::metadata()` after a round
  trip)? If not, the Markdown fallback should still keep types and marks; find out why it doesn't either.
- How was the block copied: text selected inside one block (ADR 0030 makes that a `Text` fragment, which keeps
  marks but not the block type), whole blocks selected, or the block menu? Decide with the owner what copying
  one block's full text should carry; Notion carries the block type when the whole block is selected.
- Is anything on the clipboard at all when only a caret (no selection) is in the block?

## Acceptance criteria

- [x] Selecting one or more whole blocks, copying and pasting inside Leaf recreates the same types, marks and nesting
- [x] Copying text inside one block and pasting keeps its marks
- [ ] Works on macOS through the real system clipboard (checked by the owner), not only in the test clipboard
- [x] If the pasteboard drops the metadata, the Markdown fallback still restores types and marks
- [x] A failing test reproduces the bug before the fix
- [ ] Tests added; `just check` passes; docs updated if structure changed

## Plan

- Cause (no answer from the owner on how they copied, so all three ways were checked): the macOS pasteboard keeps
  Leaf's fragment fine (GPUI stores it with a text hash). But selecting a block's text copied plain formatted text
  by design (ADR 0030), so a heading pasted as a paragraph; and Cmd+C with only the caret copied nothing, so the
  paste was whatever plain text was on the clipboard before. Whole-block selections already kept their kind.
- `clipboard.rs`: all of one block's text, or the caret alone, copies the block (`Blocks`, no children). Cut still
  needs a selection. Pasting blocks takes the line's kind only when the line is empty, not merely at its start.
- Tests: editor (`clipboard/tests/whole_blocks.rs`) and a window test through the test clipboard. PRODUCT_SPEC
  editor rule and ADR 0030 amended.
