## Context

Found by a security and code-smell review of the repo tooling (2026-10-31). The repository is public, but
`ci.yml` runs with the default token scope, and the third-party actions are pinned to moving tags (`@v1`, `@v2`), so
a compromised action release would run in our CI. `deny.toml` also only warns on duplicate crate versions and unknown
git sources, so neither ever fails the build.

## Acceptance criteria

- [ ] `ci.yml` declares `permissions: contents: read` at the top level; any job that needs more asks for it itself
- [ ] Every third-party action is pinned to a full commit SHA, with the version tag in a comment
- [ ] `.github/dependabot.yml` keeps `github-actions` and `cargo` up to date (weekly, grouped to limit PR noise)
- [ ] `deny.toml`: `unknown-git = "deny"` with GPUI's git source in `allow-git`; `multiple-versions = "deny"` with a
      `skip` list for today's unavoidable duplicates, each with a reason
- [ ] The owner is asked to turn on secret scanning and push protection in the repo settings (not doable from code)
- [ ] ADR recording the supply-chain policy; `just deny` and `just check` pass; PR CI green
