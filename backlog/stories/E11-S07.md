## Context

Prove search meets its budget on a large workspace.

## Acceptance criteria

- [ ] Fixture: 5,000 pages, ~100k blocks (reuse E08-S01 fixtures)
- [ ] Query results in < 50 ms (p95) on that fixture
- [ ] Re-indexing one edited page takes < 20 ms
- [ ] Full rebuild time measured and recorded in the story Log
- [ ] Benchmarks added; `just check` passes

## Plan

- A benchmark binary `crates/leaf-search/benches/search.rs` (`harness = false`, so no new dependency; E08-S02 brings
  divan for the editor benches). `leaf-fixtures` becomes a dev-dependency of `leaf-search`.
- It builds the full-size fixture (seed 42: 5,000 pages × 20 blocks = 100,000 blocks) into an in-memory
  `PageSource` (saved bytes and versions, like the store), then measures on a real index file in a temp folder:
  1. **Full rebuild:** `Syncer::rebuild` once, timed (recorded in the Log).
  2. **Queries:** a fixed list of queries (single words, two words, a prefix, accented and non-Latin words, a very
     common word, a miss), each run many times through `Searcher` (the read-only connection the search bar uses);
     p50, p95 and worst over all runs. Budget: p95 < 50 ms.
  3. **Re-index one edited page:** save a changed version of one page, then time `Syncer::reconcile` (the
     worker's real path: read versions, skip unchanged pages, re-read and re-index the one that changed), many
     rounds; p95. Budget: < 20 ms.
- Prints a table and exits non-zero when a budget is missed. `just bench-search` runs it; `just bench` already
  runs every bench.
- Risk: the fixture's small vocabulary makes common words match almost every page, the worst case for ranking.
  That is deliberate; if it misses the budget, the fix belongs in the query, not the benchmark.
