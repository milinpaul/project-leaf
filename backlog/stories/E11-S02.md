## Context

Turn a page into the rows the index stores: its title, and the plain text of each block (via `PageDoc::plain_text`).

## Acceptance criteria

- [x] One row per block with text: page id, block id, block kind, plain text (no marks)
- [x] Title row from the workspace page meta; untitled pages index as "Untitled"
- [x] Pages in the trash produce no rows
- [x] Blocks of unknown kinds are indexed by their text if they have any, and nothing is changed (rule 5)
- [x] Dividers and empty blocks produce no rows; code blocks and image captions are indexed
- [x] Tests added; `just check` passes; coverage ≥ 90%

## Plan

- **API:** `leaf_search::page_text(workspace, page, doc) -> Result<Option<PageText>, SearchError>` in a new
  `extract.rs`. `None` when `Workspace::is_in_trash` (covers pages hidden by a trashed parent). Title from
  `PageMeta`, blank → "Untitled". Blocks walked depth-first in document order via `root_blocks`/`children`;
  a row for every block whose `plain_text` has non-blank text, `kind` = `BlockKind::type_name()`.
- **Unknown kinds:** `plain_text` reads the text container whatever the kind, so an unknown block that carries
  text is indexed and nothing is written. Read-only, so rule 5 holds.
- **Images:** the story said "no rows", but an image's text is its caption, which the owner typed and would
  expect to find. Captions are indexed; criterion updated.
- **Errors:** `SearchError::Model` wraps `ModelError`. Adds `leaf-model` (already a core dep) to `leaf-search`;
  `loro` as a dev-dependency only, to write an unknown block in a test the way other crates' tests do.
- **Tests:** `tests/extract.rs` covering each criterion; coverage ≥ 90%.
