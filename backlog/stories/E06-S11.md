## Context

A page can have a cover: a full-width band above the title, like Notion. The icon sits over the cover's bottom
edge, half on it and half below. Agreed with the owner on 2026-10-29; polish, so it must not hold up the Phase 0
acceptance pass.

Store the cover on the page next to `title` and `icon` in the workspace doc, so the sidebar and header know it
without opening the page. Built-in covers are saved by a stable name (`builtin:<name>`), not as an image, so a
later "upload your own" can reuse the asset store without changing the format.

## Acceptance criteria

- [ ] Workspace doc page meta gets an optional `cover`; `SetPageCover { page, cover: Option<String> }` sets or clears it as one undo step, and setting the same cover is `Unchanged`
- [ ] An unknown cover name (from a newer version) is kept and shown as a neutral band, never dropped (rule 5); `cover` survives page moves, trash and restore
- [ ] Header: on hover, **Add cover** sits beside **Add icon**; over a cover, **Change cover** and **Remove** appear
- [ ] Change cover opens a picker popover with thumbnails of the built-in covers; choosing one applies it; Esc closes
- [ ] With a cover the band is full width, about 200–240 px tall, and the icon overlaps its bottom edge; without one the header is unchanged
- [ ] Covers are drawn in code (gradients/shapes) or from bundled vector files; the first step checks GPUI draws full-colour vector files and records the choice in an ADR
- [ ] At least one placeholder cover so the story works before E06-S12
- [ ] BLOCK_MODEL.md and ARCHITECTURE.md updated; ADR added
- [ ] Tests added; `just check` passes; docs updated if structure changed
