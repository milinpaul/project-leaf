## Context

Type that owns the workspace LoroDoc and exposes read queries over the page tree.

## Acceptance criteria

- [x] Create new / load from bytes / export bytes
- [x] List root pages and children of a page in order
- [x] Get page meta (title, icon, created_at, trashed_at)
- [x] Find page by PageId in O(1) via an index map
- [x] Tests added; `just check` passes; docs updated if structure changed

## Plan

- `leaf-model/src/workspace.rs`: `Workspace` owns the workspace `LoroDoc` and its `"pages"` tree (fractional
  index on). `new`, `from_bytes` (import a snapshot), `to_bytes` (export a snapshot).
- Read API: `root_pages`, `children(PageId)`, `page(PageId) -> PageMeta`, `contains`. All by `PageId`; Loro
  `TreeID`s stay private (ADR 0006 pattern). Trashed pages are listed too, with `trashed_at` set: hiding them
  is the trash story's job (E01-S05).
- `PageId → TreeID` index (`HashMap`), rebuilt on load. Undo will rebuild it too (E01-S06).
- `page_meta.rs`: `PageMeta` and the meta key names. `error.rs`: `ModelError` (unknown page, invalid page data,
  Loro errors).
- Loading is strict: a page without a valid `id` fails to load with a clear error, rather than being hidden.
- Tests build workspaces through raw Loro writes in test code, since the page commands arrive in E01-S03.
- Risk: none known. Loro builds for wasm32 as-is (checked).
