## Context

Render and edit the page tree.

## Acceptance criteria

- [x] Expand/collapse persisted
- [x] Create, rename inline, delete to trash via context menu
- [x] Drag to move and reorder
- [x] Smooth with 500 pages, 6 levels deep
- [x] Tests added; `just check` passes; docs updated if structure changed

## Plan

- **Model (`leaf-model`)**: add `Workspace::parent(page)` and `Workspace::child_slots(parent)` (all children, trashed
  included) so the editor can turn "drop before/after/inside this row" into a model index (indexes count trashed
  pages; listings hide them).
- **Editor (`leaf-editor`, new `page_tree` module)**: sidebar rows become the flattened visible tree (depth, has
  children, expanded). `WorkspaceEditor` gains an expanded set, `toggle_expanded`, `new_page_in(parent)`, `rename`,
  `trash` (clears the selection when the open page goes), `move_page(page, DropPlace)`, `can_drop` and
  `drop_place(offset, height)` (top quarter = before, bottom quarter = after, middle = inside). After an expanded
  page with children = its first child. Fixes `new_page` inserting among trashed pages at the wrong slot.
- **Store (`leaf-store`, `view_state`)**: `view.json` in the workspace folder holds expanded page IDs. Local view state,
  not a document: not synced, no undo, unknown fields kept, damaged file = defaults. Saved when it changes.
- **UI (`leaf-ui`, `shell/tree`)**: own sidebar column (same tokens) with a `uniform_list` so only visible rows render
  (500 pages smooth); chevron, indent, context menu (Add page inside, Rename, Move to Trash), inline rename input
  (Enter/blur commits, Esc cancels), drag with before/after/inside indicator.
- **Tests**: editor unit tests for every action and index mapping incl. trashed siblings; proptest that random moves
  keep visible order consistent with the requested drop; timing test for 500 pages × 6 levels; store tests for
  `view.json`; gpui tests for toggle, rename, trash, drag-drop via editor.
- **Docs**: ADR 0030 page tree, ARCHITECTURE, BLOCK_MODEL (new queries), screenshots.
- **Risks**: gpui drag tests are awkward, so drop logic is tested in the editor and the UI only forwards.
