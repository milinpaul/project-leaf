## Context

Quitting Leaf and opening it again shows the empty "Create a page" screen, even though a page was open. The
owner wants the page that was open when the app closed to open again. Which page is open is a per-computer
convenience, like which sidebar pages are expanded, so it belongs in the workspace's `view.json` (never synced,
never an edit, never undone), not in the workspace document.

## Acceptance criteria

- [x] Opening a page (from the sidebar, search, the quick switcher, a new page) records it in `view.json`, written only when it changes
- [x] Opening the workspace again opens that page, scrolled to the top, as if it had been clicked
- [x] A page that is gone or in the trash isn't reopened; the workspace opens as it does today
- [x] Each workspace remembers its own page; an older `view.json` without the entry still loads
- [ ] Checked on macOS by the owner
- [ ] Tests added; `just check` passes; docs updated if structure changed

## Plan

- `leaf-store` `ViewState`: `open_page` / `set_open_page`, kept as text like `expanded` (a bad ID is ignored).
- `leaf-editor` `WorkspaceEditor::restore_open_page(Option<PageId>) -> bool`: selects it only if it exists and is
  not in the trash. Unit tests.
- `leaf-ui`: `Storage::open_page` / `save_open_page` (writes only on change); `Shell::with_storage` restores it after
  the expanded pages and shows it; `show_selected` (every way a page is opened) records it. Window test reopening a
  workspace from a temp folder.
- ARCHITECTURE.md (view state) and the ADR on view state amended.
