## Context

Owner request: see the model working in the real window early, long before the full sidebar (E06-S03) which
waits for undo and saving. Replace the spike's three placeholder pages with the pages of a real in-memory
`Workspace`: list them, add one, rename one. Nothing is saved yet; that arrives with E03.

## Acceptance criteria

- [x] Sidebar lists the workspace's root pages from the model, in order (no hard-coded titles)
- [x] A "New page" action creates a page through the page commands and it appears in the sidebar
- [x] Renaming a page through the page commands updates the sidebar
- [x] UI only renders and forwards: page list logic lives in a testable crate, not `leaf-ui`
- [x] Screenshot of the running app attached to the PR
- [x] Tests added; `just check` passes; docs updated if structure changed

## Plan

- **`leaf-editor/src/workspace_editor.rs`:** `WorkspaceEditor` owns a `Workspace` plus the selected page.
  - `sidebar()` returns view-model items for the top-level pages, with trashed pages hidden and "Untitled"
    shown for empty titles.
  - `new_page(now_ms)` appends a page at the end and selects it.
  - `select(page)`, and `rename_selected(title)`, which does nothing if the title is unchanged.
  - All logic is here, unit-tested and inside the coverage gate.
- **`leaf-ui` `Shell`:** holds a `WorkspaceEditor`. The sidebar lists `sidebar()` items, with the active one
  highlighted, and has a "New page" button. The page area shows the selected page's title in the input:
  typing renames, and the sidebar updates on the next frame. The app supplies the clock, so the model never
  reads it. Also fixes the spike's vertically centred page area.
- **Tests:** editor unit tests, plus GPUI tests for new page → type → renamed, and selecting a page loads its title.
- **Visual check:** run the app, create pages, rename one, and take a screenshot into `docs/screenshots/`.
- **Scope:** top-level pages only, matching the acceptance criteria. Nesting, move and trash in the sidebar
  stay with E06-S03.
