## Context

Found by a security and code-smell review of the repo tooling (2026-10-31). `leaf-store/src/assets/kind.rs`
recognises SVG images. SVG is XML: a file can point at external files or URLs, expand entities, or describe a
huge or deeply nested picture. Rendering one must never read other files on disk, make a network request
(architecture rule 6), or exhaust memory.

## Acceptance criteria

- [x] Find out how SVGs are decoded and rendered today (which crate, which options) and write it down in the Plan
- [x] External references (`href` to files or URLs, `<image>`, external CSS/fonts) are never loaded
- [x] Size limits: file size, rendered pixel size and nesting depth are capped; over the cap shows a placeholder
      with an error, and the original file is kept unchanged (rule 5)
- [x] Tests with crafted SVGs: an external `href`, a `file://` image, a "billion laughs" entity file, a huge
      `viewBox`, deep nesting
- [ ] ADR if a renderer option or limit is chosen; `just check` passes

## Plan

How SVGs are drawn today: `leaf-ui/src/shell/image_row.rs` hands the asset's path to GPUI's `img()`. GPUI
(`gpui-pre` 0.3.10, `elements/img.rs`) decodes anything `image::guess_format` doesn't recognise as an SVG with
`usvg` 0.46 on **default options**: its `default_string_resolver` reads any image file an `href` names, absolute or
relative to the working directory (PNG, JPEG, GIF, WebP, and nested SVGs with the same options); it has no network
code. The picture is rasterised at **twice** its own size (`SMOOTH_SVG_SCALE_FACTOR`), with no cap. XML is parsed
by roxmltree with DTDs allowed; roxmltree already stops entity loops and "billion laughs" expansion. Leaf can't
change GPUI's usvg options, so it checks the SVG before handing it over.

- `leaf-store/src/assets/svg.rs`: `check_svg(bytes) -> Result<(), SvgProblem>` with roxmltree (already in the tree
  through usvg; same options): refuse any `href` (either namespace) or CSS `url()` that isn't `#id` or an embedded
  PNG/JPEG/GIF/WebP `data:` URL, any `@import`; cap file size (10 MB), nodes (250,000), depth (256), and the picture
  size usvg would use (side ≤ 8,192 CSS px, area ≤ 8 M px).
- `Workspace::drawable_asset(id)`: raster files by their first bytes pass; anything else is checked as an SVG.
- `leaf-ui` image row: checks once per asset (cached), draws the frame with the reason on refusal. The file is
  never changed (rule 5). Built-in covers are Leaf's own files and aren't checked.
- Tests: unit tests for every rule and limit (each fails with the check disabled), store integration tests, UI
  tests (outside reference shows the frame; a plain SVG draws). ADR-XXX-E08-S12.
