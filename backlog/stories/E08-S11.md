## Context

Found by a security and code-smell review of the repo tooling (2026-10-31). `SECURITY.md` names the most relevant
threat: a crafted workspace, image or pasted content that crashes Leaf or makes it lose data. Proptest covers
command sequences, but nothing yet feeds Leaf arbitrary bytes. Fuzzing finds panics, hangs and memory blow-ups
in code that reads outside input.

## Acceptance criteria

- [x] `cargo-fuzz` targets (in a `fuzz/` crate outside the workspace's normal build) for: loading a Loro snapshot or
      update into a document, opening a workspace database, asset type sniffing (`leaf-store/src/assets/kind.rs`),
      and pasted text/HTML/Markdown turned into blocks
- [x] Each target checks: no panic, no hang, bounded memory; bad input gives an error, never a crash
- [x] A seed corpus from the test fixtures, and a `just fuzz <target> [seconds]` task
- [x] Each target runs for at least 10 minutes locally without findings; anything found is fixed with a regression
      test first (or split into an E17 bug story)
- [x] A scheduled or manual CI job runs each target for a short time (never on PRs)
- [x] ADR on the fuzzing setup; `docs/architecture/ARCHITECTURE.md` mentions it; `just check` passes

## Plan

- **`fuzz/` crate** (cargo-fuzz layout, its own `[workspace]` and lock file; the main workspace excludes it, so
  `just check` and normal builds never compile it). Needs nightly Rust only for `cargo fuzz`; the pinned toolchain
  stays for everything else.
- **Four targets:**
  - `doc_bytes`: bytes into `PageDoc::from_bytes`, `Workspace::from_bytes`, `Database::from_bytes` and
    `import_changes` on fresh documents; when one loads, walk it (blocks, text, kinds, invariant check).
  - `workspace_db`: bytes written as `workspace.sqlite` in a temp folder, then what the app does on open:
    `leaf_store::Workspace::open`, load the workspace document, load every page and database it names; also
    `ViewState::load` on bytes as `view.json`.
  - `asset_kind`: `image_mime`, `check_svg`, and `import_asset` into a temp workspace.
  - `paste`: bytes as text into `PageEditor::paste_text` on a small page (in a paragraph and in a code block),
    and as JSON into `Fragment::from_json` then `paste`; the page must still pass its invariants. Leaf has no
    HTML paste parser yet (the OS clipboard gives it text or its own fragment JSON), so there is no HTML target.
- **Limits:** `just fuzz <target> [seconds]` runs with `-timeout=5` (hang), `-rss_limit_mb=2048` (memory) and a
  `-max_len` per target. Seeds: `crates/leaf-fixtures/examples/fuzz_seeds.rs` writes a seed corpus (fixture
  documents and workspaces, sample images and SVG, Markdown and fragment samples); the task runs it when the
  corpus is missing.
- **CI:** `.github/workflows/fuzz.yml`, weekly schedule plus manual run, each target for a few minutes. Never on PRs.
- **Findings:** each fixed with a failing regression test first, or filed as an E17 bug story if large.
- **Docs:** ADR-088 on the setup, ARCHITECTURE.md testing section, CONTRIBUTING mention.
- **Risks:** SQLite fuzzing is slow per run (a few ms); Loro may panic on crafted bytes inside the library
  (would need catching or an upstream report).
