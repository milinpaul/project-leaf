## Context

Found by a security and code-smell review of the repo tooling (2026-10-31). `SECURITY.md` names the most relevant
threat: a crafted workspace, image or pasted content that crashes Leaf or makes it lose data. Proptest covers
command sequences, but nothing yet feeds Leaf arbitrary bytes. Fuzzing finds panics, hangs and memory blow-ups
in code that reads outside input.

## Acceptance criteria

- [ ] `cargo-fuzz` targets (in a `fuzz/` crate outside the workspace's normal build) for: loading a Loro snapshot or
      update into a document, opening a workspace database, asset type sniffing (`leaf-store/src/assets/kind.rs`),
      and pasted text/HTML/Markdown turned into blocks
- [ ] Each target checks: no panic, no hang, bounded memory; bad input gives an error, never a crash
- [ ] A seed corpus from the test fixtures, and a `just fuzz <target> [seconds]` task
- [ ] Each target runs for at least 10 minutes locally without findings; anything found is fixed with a regression
      test first (or split into an E17 bug story)
- [ ] A scheduled or manual CI job runs each target for a short time (never on PRs)
- [ ] ADR on the fuzzing setup; `docs/architecture/ARCHITECTURE.md` mentions it; `just check` passes
