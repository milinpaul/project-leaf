## Context

`backlog/backlog.json` is generated from the story files but committed, so any two PRs that touch stories
conflict on it (seen merging main into E00-S08 after PR #4). The fix today is to regenerate it. Options: mark it
`merge=ours` plus regenerate in a hook, or stop committing it and build it on demand (CI check would change).

## Acceptance criteria

- [x] Two PRs that each change a different story merge without a backlog.json conflict
- [x] CI still fails when the backlog is invalid
- [x] Tests added; `just check` passes; docs updated if structure changed

## Plan

- **Approach:** stop committing `backlog.json` (option 2). Nothing reads the committed copy: the board embeds
  its own data and is already gitignored, and the live board serves JSON from memory. A `merge=ours` attribute
  would not help, because GitHub's merge button ignores custom merge drivers.
- **Changes:** add `/backlog/backlog.json` to `.gitignore` and untrack it. `backlog.py --check` validates only
  (still exits 1 on any invalid story or epic) and writes nothing. Hooks, `just backlog` and the commands still
  write it locally for anyone who wants it.
- **CI:** the `backlog` job keeps its name (it may be a required check) and runs the new script tests too.
- **Tests:** `scripts/test_backlog.py` (stdlib `unittest`, run by CI and `just check`): `--check` passes and
  writes nothing on a valid copy, fails on an invalid one; a temp git repo where two branches each move a
  different story merges cleanly.
- **Docs:** `backlog/README.md`, the backlog skill and CLAUDE.md lines about `backlog.json`.
- **Side effect:** also removes the dirty-tree problem in E00-S07 for `backlog.json` (only untracked files are
  written now); noted there, left for the owner to close.
