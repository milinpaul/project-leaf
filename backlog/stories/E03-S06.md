## Context

Prove the ≤ 1 s data loss guarantee.

## Acceptance criteria

- [x] Test drops the store without flush and reloads
- [x] Loses nothing older than the flush interval
- [x] Corrupt trailing update is skipped with a warning, not a failed load
- [x] Tests added; `just check` passes; docs updated if structure changed

## Plan

- **Crash simulation:** copy `workspace.sqlite` and its `-wal` file while the app still has them open. That is
  exactly what a killed process leaves on disk. Then open the copy and load.
- **Property test (fake clock):**
  - random edit times, with the autosave timer firing at each deadline;
  - a crash at a random moment;
  - every edit made at least 300 ms before the crash must be in the reloaded page.
- **Corrupt updates:**
  - Loading tries the normal way first.
  - If that fails, `PageDoc::recover` / `Workspace::recover` import the snapshot and then each update on its
    own, skipping the ones Loro rejects.
  - `Store::load` logs a `tracing` warning per skipped update.
  - `Store::recover` returns the skipped `seq`s, so the app can tell the user.
  - The bad row is kept on disk (never drop data).
  - If nothing could be skipped, the original error stands (for example a corrupt snapshot).
- **Why not only the last update:** skipping any rejected update matters because new saves are appended *after*
  a bad one, so it doesn't stay trailing.
- **New dependencies** (already workspace dependencies): `tracing` for the warning, `proptest` for the test.
