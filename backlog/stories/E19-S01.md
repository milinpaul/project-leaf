## Context

A new block kind for action items in `leaf-model`: rich text like a to-do, plus done, a due date, an optional due
time and a priority. Commands set each of them with undo, and two peers changing different fields converge.
Write the ADR for the shape: one kind with props (as to-do keeps `checked`), the date and time format, and how
it stays apart from the to-do kind.

## Acceptance criteria

- [x] `BlockKind::Task { done, due, time, priority }` with `Priority` High / Medium / Low and none; date as `YYYY-MM-DD`, time as `HH:MM` (24 h), both optional, time only with a date; documented in BLOCK_MODEL.md
- [x] Commands: set done, set due date (and clear), set due time (and clear), set priority; each one undo step; invalid dates and times are refused
- [x] Undo/redo round-trips and two-peer convergence (proptest)
- [x] A task from a newer version with props Leaf doesn't know keeps them when saved
- [x] Saved and reopened through `leaf-store` unchanged; ADR written and added to the index
- [x] Tests added; `just check` passes; docs updated if structure changed

## Plan

- `leaf-model/src/task.rs`: `DueDate` (validated `YYYY-MM-DD`, leap years), `DueTime` (`HH:MM`, 24 h), `Priority`
  (High/Medium/Low); parse and format, no new dependency (no `chrono`: a due date is a plain calendar date).
- `BlockKind::Task { done, due, time, priority }`, stored as meta props `done`, `due`, `due_time`, `priority`
  (ADR 0007: plain values beside `type`). Children allowed (notes nest under a task). A time needs a date.
- `BlockProp::{TaskDone, TaskDue, TaskTime, TaskPriority}` through the usual `SetProp`; clearing the date clears the
  time too. Two devices changing different fields keep both: Loro skips writing an unchanged value, so rewriting the
  kind touches only the changed key (checked by a test that fails if it didn't; a per-field write was tried and
  dropped as unnecessary).
- Other crates: the editor draws a task as a to-do until E19-S02/S03; the clipboard carries it as its own type
  (`"type": "task"` + props) so nothing is lost; Markdown out writes a to-do line until E19-S04.
- Tests: unit tests for parsing; model tests (create, set each field, undo/redo, invalid input refused, unknown
  props kept, reload); proptest convergence with task steps. ADR 0068 + BLOCK_MODEL.md.
