## Context

Persist Loro snapshots and incremental updates.

## Acceptance criteria

- [x] Append update per commit batch
- [x] Load = snapshot + updates in seq order
- [x] save→load equality test for workspace and page docs
- [x] Tests added; `just check` passes; docs updated if structure changed

## Plan

- **`leaf-model`:** `Workspace` and `PageDoc` remember the version they were last saved at.
  - `from_saved(snapshot, updates)` loads a document.
  - `unsaved_changes()` returns one Loro update covering every commit since the last save, or `None` if nothing
    changed.
  - `mark_saved()` is called after a successful write.
  - This keeps Loro types out of the store.
- **`leaf-store`:**
  - **`DocKey`:** `Workspace`, or `Page(PageId)`; the `doc_id` text is `workspace` or the page's ID.
  - **`Document` trait:** implemented for both model types.
  - **`Store::save(key, doc, now_ms)`:**
    - when the document has no row yet, it writes a snapshot;
    - otherwise it appends the unsaved changes as one row in `doc_updates` (one row per batch of commits);
    - it writes nothing when nothing changed.
  - **`Store::load(key)`:** the snapshot, then the updates in `seq` order; `None` if the document was never saved.
  - The caller passes the time, so autosave (E03-S04) can test with a fake clock.
- **Tests:**
  - save→load equality for the workspace and for pages over several save rounds, including undo, after reopening
    the folder;
  - no write when nothing changed;
  - one update row per save;
  - updates read in `seq` order;
  - docs kept apart.
- **Out of scope:** compaction (E03-S05), the autosave timer (E03-S04), and wiring into the UI.
