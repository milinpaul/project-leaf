## Context

The `main` run for #241 failed on macOS: the page undo property test (10,000 cases) found a sequence with a web
bookmark (E15-S02, ADR-083) where redo loses a step. A fetched preview is written off the undo history; turning a
bookmark "into" the same bookmark (`SetBlockKind` with its own address) cleared the preview as a user step, and when a
preview arrived again afterwards, undoing that step left nothing for redo:

insert a bookmark → preview arrives → `SetBlockKind` (same address) → preview arrives → undo, undo → redo gives only one
step back. A related case shows a wrong card: change the address, a preview for the new address arrives, then undo
brings back the old address with the new address's preview (undo can't take back what it never recorded).

## Acceptance criteria

- [x] Failing tests first for both cases (the second already passed: Loro's undo restores the old preview, so it stays as a guard)
- [x] Turning a bookmark into a bookmark of the same address changes nothing (its preview stays)
- [x] Undo never shows a preview fetched for another address (checked by a test; nothing more needed)
- [x] The CI case is a unit test; the property tests pass with 10,000 cases (twice, fresh seeds)
- [x] BLOCK_MODEL.md updated (no new decision); `just check` passes

## Plan

- `kind_ops::set_kind`: a bookmark turned into a bookmark of the same address is left alone (Unchanged).
- Two failing-first tests in `web_bookmark_tests.rs`; property tests at 10,000 cases.
