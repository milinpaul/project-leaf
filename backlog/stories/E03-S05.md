## Context

Snapshot and prune when a doc has > 200 updates.

## Acceptance criteria

- [x] Compaction is one transaction
- [x] Doc state identical before and after
- [x] Test with interrupted compaction (rollback) keeps data
- [x] Tests added; `just check` passes; docs updated if structure changed

## Plan

- `leaf_model::fold_saved(snapshot, updates)`: import into a plain `LoroDoc`, export a full snapshot (history and
  unknown data kept); `None` when an update waits for a lost one, error when one is damaged.
- `Store::compact(key)` in `leaf-store/src/compaction.rs`: one immediate transaction; count updates, and past
  `COMPACT_AFTER` (200) read, fold, write the snapshot, delete the updates, commit. Keeps `updated_at` at the last
  edit. Damaged or orphaned updates: skip with a warning (ADR-012).
- `Store::save` calls it after appending an update; a compaction error is logged, not returned.
- Tests: `leaf-store/tests/compaction.rs` (limit, identical page with marks, saving after, interrupted compaction
  via a SQLite trigger that aborts the delete, damaged update, lost update, workspace doc); `saved/tests.rs` in
  `leaf-model` (history and unknown containers survive).
- Docs: ADR-048, BLOCK_MODEL persistence, ARCHITECTURE step 5, `SavedVersion` doc.
- Risk: search sees the version change and re-reads the page once; harmless.
