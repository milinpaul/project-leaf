## Context

The star in the top bar adds a page to Favourites. The workspace document keeps an ordered list of favourite pages,
changed only through commands, so it is saved, undoable and will sync.

## Acceptance criteria

- [x] `AddFavourite` and `RemoveFavourite` workspace commands; favourites keep the order they were added in; adding twice does nothing
- [x] A trashed page drops out of the favourites list shown; restoring it puts it back; deleting it for good removes it
- [x] Undo round-trip and two-peer convergence covered by property tests (both peers starring the same page ends with it once)
- [x] `WorkspaceEditor` exposes the favourites as sidebar items and whether a page is a favourite
- [x] BLOCK_MODEL.md updated; compiles for `wasm32-unknown-unknown`
- [x] Tests added; `just check` passes; docs updated if structure changed

## Plan

- **Model** (`leaf-model`, new `workspace/favourites.rs`): a root map `"favourites"` in the workspace doc, key =
  `PageId`, value = position (i64). `AddFavourite { page }` stores max + 1 (so it goes last); already there →
  `Unchanged`; a trashed page is refused. `RemoveFavourite { page }` deletes the key; not there → `Unchanged`.
  `Workspace::favourites()` lists them by (position, id), leaving out pages in the trash (directly or inside a
  trashed page) and entries whose page is gone; `is_favourite(page)`. Entries a newer version wrote in another
  shape are skipped but kept (rule 5).
- **Trash:** trashing leaves the entry, so restoring brings it back in place; `DeletePagePermanently` removes the
  entries of every deleted page in the same commit (undo brings both back).
- **Why a map, not a list:** two devices starring the same page write the same key, so it is there once; a list
  would hold it twice. Same-moment positions tie-break by page id, so both devices show the same order.
- `Workspace::import_changes(bytes)` (like `PageDoc`'s, rebuilding the index) so tests can merge two peers; no sync
  yet.
- **Editor:** `favourites()` as `SidebarItem`s (depth 0, selected like the tree), `is_favourite`,
  `set_favourite(page, on)`.
- **Tests:** unit tests for each rule; the workspace undo proptest (`tests/page_history.rs`) gains favourite steps
  and the favourites list in its outline; a new two-peer proptest checks convergence and "starred on both, listed
  once".
- **Docs:** ADR-060, BLOCK_MODEL workspace doc and commands.
