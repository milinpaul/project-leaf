## Context

The owner wants Leaf in `/Applications` on their Mac before real installers exist (E08-S04). One command should
build an optimised Leaf, wrap it in `Leaf.app` (reusing `scripts/macos_app.py` from E08-S05) and put it in
`/Applications`, replacing an older Leaf but never someone else's app that happens to be called `Leaf.app`.

## Acceptance criteria

- [x] `just install` (macOS) builds a release Leaf and installs `/Applications/Leaf.app`; running it again updates it
- [x] An existing `Leaf.app` with a different bundle ID is left alone and the command fails with a clear message
- [x] Tests added; `just check` passes; docs updated if structure changed

## Plan

- `scripts/macos_app.py`: split bundle-making into `make_bundle()`; add `install <binary> [<dir>]` mode that builds
  the bundle beside the binary and copies it into `<dir>` (default `/Applications`). An existing `Leaf.app` is
  replaced only if its `CFBundleIdentifier` is ours; otherwise refuse with a message.
- `justfile`: `[macos] install` = `cargo build --release --locked -p leaf-app` + the script's install mode.
- Tests: `scripts/test_macos_app.py` (standard library, runs on Linux CI): fresh install, update replaces old
  files, foreign `Leaf.app` refused and untouched, broken Info.plist refused.
- Docs: ARCHITECTURE.md app-identity paragraph; ADR-018 consequence line. No new dependencies.
- Risk: can't run on a Mac here; the recipe is two commands, the logic lives in the tested script.
