## Context

Found by a security and code-smell review of the repo tooling (2026-10-31). A crafted workspace can claim millions
of blocks, very deep nesting, or an image with huge dimensions, and Leaf would try to load or decode it all. Load
paths need explicit caps that fail with an error instead of running out of memory or stack, without ever
dropping data from the file (architecture rule 5).

## Acceptance criteria

- [ ] Caps chosen and documented for: document size, block count per page, nesting depth (no recursion that can
      overflow the stack), image file size and decoded pixel count, pasted content size
- [ ] Image dimensions are checked from the header before the full decode
- [ ] Hitting a cap shows a clear message (the page or image opens read-only or as a placeholder); the file on disk is
      left unchanged
- [ ] Caps sit well above the Phase 0 performance fixtures (5,000 pages, 100,000 blocks), and those tests still pass
- [ ] Tests for each cap; ADR with the chosen limits and why; `just check` passes
