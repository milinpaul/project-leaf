## Context

The owner wants the cover picker to look like Notion's gallery: a "Gallery" tab with "Remove" on the right, then
sections of wide, rounded thumbnails in a grid, four to a row. They also want new built-in covers in soothing solid
colours and gradients, shown first under "Colour & gradient", with the six existing covers below them.

Upload, Link and Unsplash tabs are out of scope (no network in Phase 0; uploads need their own story). Reposition
is out of scope too.

## Acceptance criteria

- [x] The picker shows a "Gallery" tab header with "Remove" on the right while the page has a cover
- [x] Covers are grouped in sections ("Colour & gradient", then "Illustrations"), as a grid of rounded thumbnails, four per row; the picker scrolls if it is taller than the window allows
- [x] The page's current cover is outlined in the picker
- [x] New soothing solid-colour and gradient covers, each under a stable `builtin:` name that never changes once shipped; they look good in light and dark mode
- [x] Previews shown to the owner before merge (approved 2026-10-30)
- [ ] Tests added; `just check` passes; ADR and docs updated

## Plan

- 16 new `BuiltinCover`s (8 solid, 8 gradient), each a tiny SVG generated once by a throwaway script and checked on
  a contact sheet, then in the app in light and dark mode.
- `CoverSection` in `leaf-editor` groups covers; `BuiltinCover::section()`.
- `leaf_ui::covers` becomes one (cover, path, bytes) table.
- `CoverPickerPanel` takes the current cover: Gallery tab row with Remove, sections in a scrolling list, thumbnails
  four per row, current one outlined; new `CoverPicked::Remove`.
- Tests: section order and stored names (editor), grid layout, every cover offered, Remove in the picker (UI).
- ADR 0061; ARCHITECTURE and PRODUCT_SPEC lines.
