## Context

Schema from docs/architecture/BLOCK_MODEL.md plus a forward-only migration runner.

## Acceptance criteria

- [x] WAL mode enabled
- [x] meta.schema_version tracked
- [x] Migration from empty DB tested
- [x] Tests added; `just check` passes; docs updated if structure changed

## Plan

- **`leaf-store`:** `Store::open(path)` opens or creates the SQLite file and sets the pragmas: `journal_mode=WAL`,
  `synchronous=NORMAL` (with WAL, a committed transaction survives an app crash; that is the 1 s guarantee in the
  spec, and losing the last moments to a power cut is accepted), and `foreign_keys=ON`.
- **`migrations.rs`:** a numbered, forward-only list of SQL migrations. Version 1 is the BLOCK_MODEL.md schema
  (`docs`, `doc_updates` plus its index, `assets`, `meta`). Each pending migration runs in its own transaction
  together with its `meta.schema_version` bump, so a failure leaves the file as it was. A file newer than this app
  is refused with `SchemaTooNew` and left untouched.
- `StoreError` (thiserror) wraps SQLite errors.
- **Tests:**
  - a new file gets version 1, all tables and the index;
  - WAL mode is active;
  - reopening doesn't re-run migrations;
  - a newer file is refused and untouched;
  - a failing migration rolls back.

  A tiny temp-dir helper in tests avoids adding a dependency.
- **Risk:** `rusqlite`'s bundled SQLite (C) adds build time; `leaf-store` is native-only, so WASM is unaffected.
