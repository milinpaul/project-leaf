## Context

The six built-in covers (E06-S12) are hand-built SVG files. A test on 2026-10-29 with an image model (GPT image)
produced a Travel cover that looks clearly richer, using a prompt that spells out every constraint (below). Measured
against the app's needs:

- **Worked:** better look; kept everything inside the central strip, so the 4:1 crop loses nothing; mid-tones suit
  light and dark mode; 20 KB as WebP (quality 85) after cropping, about the same as the SVG; still readable as a
  128 × 32 thumbnail.
- **Didn't:** ignored the horizontal safe margin (the compass sat at ~95% of the width and was cut off in normal and
  narrow windows); added a stray loop to the dashed path; maximum output is 1536 px wide, while a very wide window on
  a Retina screen needs ~3,900 px across the band, so it looks soft there; consistency across a set of six is
  untested.

The owner generates the images (no network in the app; images are made once at design time and bundled). This story
finds out whether a full set holds up, and if so swaps the covers that are better as images.

## The prompt

Change only the `Theme:` line and the `SUBJECT` paragraph per cover.

```
Create a wide decorative cover banner for the top of a page in a calm, minimal notes app.
Theme: TRAVEL.

SUBJECT
A soft vintage map on warm sand-coloured paper: faint topographic contour lines, a thin
dashed flight path curving gently from left to right, a small white paper plane sitting
on the path and pointing along it, a terracotta map pin where the path starts and a teal
map pin where it ends, and a small compass rose.

STYLE (must match a set of six covers: dawn, forest, ocean, paper, night, travel)
- Flat vector illustration, clean simple shapes, soft gentle gradients.
- Muted pastel palette: sand, cream, soft teal, terracotta, slate blue. No neon, no pure
  black, no pure white areas larger than a small detail.
- Calm and uncluttered, plenty of empty background. No photorealism, no 3D, no hard or
  cast shadows, no grain or noise texture, no fine hairline detail.

CANVAS AND CROPPING
- Landscape image, 1536 x 1024. It will be cropped to the central 1536 x 384 strip (4:1).
  Put EVERY meaningful element inside that central horizontal strip (the middle 37% of the
  height). Above and below it, only plain continuous background that can be cut away.
- On screen the banner is cropped again: in wide windows to about 6:1 (more of the top and
  bottom of that strip cut off), in narrow windows to about 3:1 (sides cut off). Keep all
  key elements in the middle 75% of the width and the middle 70% of the strip's height.
  The background must continue seamlessly to every edge.

UI OVERLAP ZONES (keep these areas simple, plain background only)
- Bottom-left: a large round emoji icon overlaps the banner's lower-left edge, about
  5-15% in from the left. No pins, plane or compass there.
- Bottom-right corner: two small buttons ("Change cover", "Remove") appear there on
  hover. Keep that corner calm and evenly toned so the buttons stay readable.

LIGHT AND DARK MODE
The banner sits above both a near-white page and a near-black page. Use mid-tone colours
that read well against both, with no hard white or black frame at the edges.

THUMBNAIL READABILITY
The image is also shown as a tiny 128 x 32 thumbnail in a picker, so the main shapes
(path, pins, plane) must stay recognisable when shrunk. Bold, simple silhouettes over
fine detail.

STRICTLY EXCLUDE
No text, letters, numbers, labels, captions or place names. No logos, watermarks,
signatures, people, borders, frames or vignettes.
```

## Plan

1. **Consistency check (blocked on the owner's images).** The owner generates Travel (again, compass inside the
   middle 75%), Forest and Ocean with the prompt above at 1536 × 1024 and shares them. I crop each to 4:1 from the
   vertical centre and put the three next to the current SVGs, plus simulated normal, narrow, very wide and
   thumbnail views. The owner decides which (if any) to switch. Stop here if they don't read as one family.
2. **Prepare the images.** Upscale offline 2× (to 3,072 × 768) with an AI upscaler run locally (no network in the
   app; a dev tool only, not a dependency), save as WebP at quality ~85, check each is under 100 KB.
3. **Code.** `crates/leaf-ui/assets/covers/<name>.webp` beside the SVGs; `leaf_ui::covers` gets each cover's file
   and format (SVG or WebP); `img()` already decodes both. Stored names unchanged. Test: every built-in cover's bytes
   decode with the `image` crate (WebP) or start with `<svg`.
4. **Check in the real app** (Xvfb + software Vulkan, as for E06-S12): normal, ~860 px and ~2,160 px windows, light
   and dark, picker thumbnail. Screenshots in the PR.
5. **Docs.** ADR 0045 gains "bitmap covers": WebP, the upscaler, the licence check; ARCHITECTURE.md line on covers.

WebP: GPUI's build already links the `image` crate's WebP decoder (`image-webp`), so no new dependency.
