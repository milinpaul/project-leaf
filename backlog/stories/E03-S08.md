## Context

The app still edits an in-memory workspace. Open (or create) a workspace folder at launch, load the workspace and
pages from it, run the `Autosave` timer, and flush everything on window blur and quit. Found while planning E03-S04.

## Acceptance criteria

- [x] Launch opens the last (or a default) workspace folder, creating it if missing
- [x] Edits are saved by the autosave timer; blur and quit flush everything
- [x] Relaunching shows the same pages and text (verified with screenshots)
- [x] A second app instance shows a clear "already open" message
- [x] Tests added; `just check` passes; docs updated if structure changed

## Plan

- **`leaf-model`:**
  - `has_unsaved_changes()` is a cheap version check.
  - `mark_saved` takes `&self`: saving changes no content, so it doesn't need write access.
- **`leaf-store`:**
  - An object-safe `Savable` trait; `Document: Savable` adds the loading constructors.
  - `Autosave::tick(store, docs, now)` notices unsaved documents and saves the due ones.
  - `Autosave::flush(store, docs, now)` saves everything pending, for blur and quit.
  - Polling the documents means a change can never be missed. A forgotten `changed()` call can't happen.
  - `Workspace::open_or_create(path)`.
- **`leaf-editor`:**
  - `WorkspaceEditor::insert_page(page, doc)` hands over a page loaded from disk.
  - `loaded_pages()` lists the documents to save.
- **`leaf-ui`:**
  - **`Shell` gets optional storage:** the opened folder plus `Autosave`, with no storage in tests.
  - It loads a page from disk the first time it is opened.
  - **Saving:** a 100 ms timer calls `tick`; window deactivation and app quit call `flush`.
  - `error_root(message)` shows a window with a message when the workspace can't be opened (already open,
    damaged, ...).
- **`leaf-app`:** opens the workspace given as the first argument, or else `~/Documents/Leaf/My Workspace.leaf`,
  creating it if missing.
- **Tests:**
  - tick and flush policy with a real store;
  - `has_unsaved_changes`;
  - the editor's `insert_page`;
  - a shell test: type, flush, open the folder again, and the title and text are back.
- **Screenshots:** type, quit, relaunch, and the page is still there; a second instance shows "already open".
