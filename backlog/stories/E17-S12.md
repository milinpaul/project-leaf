## Context

Found on PR #208 (2026-10-31): the coverage job failed in
`leaf-editor` `switcher::tests::opening_and_typing_with_5000_pages_is_quick`. Its best of three runs took 163 ms
against a 150 ms budget (`crates/leaf-editor/src/switcher/tests.rs`). A re-run passed. The test measures wall-clock
time. In the coverage job it runs inside an `llvm-cov` instrumented build on a shared runner, where its own comment
says a plain test build takes about 55 ms. A red PR that the PR didn't cause costs a re-run and a comment each time.

The story's real budget (50 ms in an optimised build) belongs to the benchmarks in `leaf-bench` (ADR-056), which
record numbers and never fail on a shared runner.

## Acceptance criteria

- [ ] The switcher test still checks the results (a full list, `MAX_SWITCHER_RESULTS`, for "mtg 42" over 5,000 pages) but no longer fails on
      wall-clock time in an instrumented or debug build
- [ ] The quick switcher's open-and-type time is measured in `leaf-bench` (if it isn't already), against the 50 ms
      budget
- [ ] The other wall-clock assertion in core-crate unit tests is handled the same way:
      `leaf-editor/src/workspace_editor/tree/tests.rs` (50 ms)
- [ ] `just check` passes
