## Context

Found by the owner while testing tables (2026-10-31):

1. In a table taller than the window, clicking a cell scrolls the page to somewhere in the middle. Each cell is its
   own (invisible) row in the page list, listed just after the table's row, which draws the whole grid. Keeping the
   caret in view scrolls to that invisible row, below the grid, rather than to the cell.
2. A table wider than the page scrolls sideways only with a horizontal swipe or Shift+wheel, and nothing shows that
   it can. With a mouse there is no visible way to reach the other columns. Moving the caret into an off-screen
   column with Tab or the arrows doesn't bring it into view either.

## Acceptance criteria

- [x] Clicking a cell that is on screen never moves the page; moving the caret to a cell off screen scrolls just
      enough to show that cell
- [x] A wide table shows a horizontal scrollbar that drags it sideways
- [x] The caret moving into an off-screen column scrolls the table sideways to it
- [x] Each bug starts with a failing test; `just check` passes

## Plan

- `leaf-ui` `blocks.rs` `reveal_caret`: for a caret in a cell, keep the cell in view where it was drawn (its painted
  position) with `PageList::reveal_span`, and its column with `reveal_table_column`; the table's row only if it
  hasn't been drawn yet.
- `table_row/scroll.rs`: a horizontal scrollbar (always shown while the grid overflows) in a strip under the grid,
  at the bottom of the window for a table that runs past it; the page records the list's viewport each frame.
- Window tests first: a click on a tall table, arrows down a tall table, Tab into an off-screen column, dragging the
  scrollbar on a short and a tall table.
