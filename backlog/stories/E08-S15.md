## Context

Found by a security and code-smell review of the repo tooling (2026-10-31). The workspace already denies `unsafe`
and warns on `unwrap`/`expect` and `clippy::pedantic`, but panics can still hide in slice indexing, arithmetic
overflow and lossy casts, and about 16 `#[allow]` attributes carry no stated reason.

## Acceptance criteria

- [ ] Workspace lints add: `allow_attributes_without_reason`, `panic`, `unreachable` (outside tests),
      `print_stdout`/`print_stderr` (outside examples and benches), `cast_possible_truncation`, `cast_sign_loss`
- [ ] Core crates also lint `indexing_slicing` and `arithmetic_side_effects`; each hit is fixed or kept with an
      `#[expect(..., reason = "...")]` that says why it can't fail
- [ ] Every existing `#[allow]` gets a reason or is removed
- [ ] No behaviour change: all tests and snapshots pass unchanged
- [ ] Code conventions in `CLAUDE.md` updated; ADR on the lint set; `just check` passes
