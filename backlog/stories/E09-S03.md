## Context

`DocKey::Database` in `leaf-store`, autosave and crash recovery like pages. A full-page database is a page whose content is a database. Each row is a page in the workspace document, marked as a row of its database, created together with the row (one undo step across both documents, the rule decided in ADR-066).

## Acceptance criteria

- [x] Databases save, load and recover like pages
- [x] Adding a row creates its page; deleting a row trashes it; restoring brings the row back in place
- [x] Row pages are left out of the sidebar (owner, ADR-066 answer 1) but found by search
- [x] Tests added; `just check` passes; docs updated

## Plan

- **Workspace (`leaf-model`):** page meta gains `database` (a full-page database's `DatabaseId`) and `row_of` (the
  database a row page belongs to); `PageMeta` reads both. New commands: `CreateDatabasePage` (a page that is a
  database; reports `DatabasePageCreated { page, database }`) and `CreateRowPage` (an untitled page under the
  database's page, marked `row_of`). `Workspace::apply_unrecorded` applies a command outside undo, for the row
  pages' bookkeeping.
- **Rows and undo (rule for ADR-066):** the database document decides which rows exist; each row page's trash state
  follows it. Adding a row = create its page (unrecorded) + `AddRow`; deleting = `DeleteRow` + trash its page
  (unrecorded). Undo and redo are the database's own single step, after which `reconcile_rows` trashes or restores
  row pages to match. Restoring a row page from the Trash restores its row in place (new
  `DatabaseCommand::RestoreRow`, which clears the mark without moving it).
- **Store (`leaf-store`):** `DocKey::Database(DatabaseId)` saved as `database:<id>`; `Database` is a `Document`, so
  save, load, compaction and recovery work as for pages. Search's source ignores database keys.
- **Editor (`leaf-editor`):** `WorkspaceEditor` holds loaded databases (`insert_database`, `database`,
  `loaded_databases`), creates database pages, adds, deletes and restores rows, undoes and redoes a database, and
  leaves row pages out of the sidebar (and out of `has_children`). Search walks every page, so rows are found.
- **UI (`leaf-ui`):** autosave includes loaded databases. (Opening one is E09-S05.)
- **Tests:** model (meta, commands, unrecorded, restore row), store round trips and recovery, editor (add, delete,
  undo/redo reconcile, restore from Trash in place, sidebar hides rows, search finds a row page).
- **Docs:** BLOCK_MODEL.md workspace keys and persistence, ARCHITECTURE.md, ADR-066 note on the undo rule.
