## Context

Reported by the owner (2026-10-30): after pasting a long meeting transcript (about 38,000 characters, one
paragraph), the editor hangs; nothing can be selected or clicked. Typing and drawing stay fast; turning a pointer
position into a character position does not. `PaintedLayout` (`shell/rich_text/painted_layout.rs`) asks GPUI for the
position of every character boundary one at a time, and each answer walks the text from its start, so a click, each
mouse move while selecting, and Up/Down cost time proportional to the square of the paragraph's length.

## Acceptance criteria

- [x] A failing test first: in a test window, a click and a drag-select in a ~38,000-character paragraph finish within a generous time limit
- [x] Positions are worked out in one pass over the painted line, once per frame, and give exactly the same answers as before (existing round-trip test unchanged)
- [x] Clicking, selecting with the mouse, Up/Down and the input method's point lookups stay responsive on that paragraph in the app
- [x] Tests added; `just check` passes; docs updated if structure changed

## Plan

- Reproduced: a window test with a 38,000-character paragraph took 68 s for one click and one drag. Drawing
  (12 ms frames) and typing (6 ms) were fine; the editor's own caret moves take 20–60 ms on such a block, slow but
  not a hang.
- Cause: `PaintedLayout::line_tops` and `positions` asked `TextLayout::position_for_index` for every boundary;
  each call is linear (it scans wrap boundaries and glyphs), and `byte_of` counts characters from the start, so
  each click, drag move, Up/Down and input-method point lookup was quadratic.
- Fix: new `painted_layout/boundaries.rs` computes every boundary's position in one pass from GPUI's wrap
  boundaries and glyphs (mirroring `position_for_index`, including the running maximum `x_for_index` relies on),
  cached per painted row with a `OnceCell`, so it runs at most once per frame and only for rows asked about.
- Tests: the failing test (now well under a second), plus one comparing every boundary with GPUI's own answer for
  wrapped, formatted, multi-script text with a hard line break. ADR 0038 amended.
- Checked in the real app (debug build) on a 38,000-character paragraph: real mouse clicks and drag-selections
  respond at once and select what the pointer crossed.
