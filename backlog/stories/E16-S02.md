## Context

Editing behaviour for tables in `leaf-editor` as plain, testable Rust: moving between cells, typing, and the
keys that add rows. Add the rules to PRODUCT_SPEC.md "Editor behaviour" and give each a test.

## Acceptance criteria

- [x] Tab / Shift+Tab move to the next / previous cell; Tab in the last cell adds a row
- [x] Arrow keys move within a cell's text, then to the neighbouring cell at the edge; Enter inserts a line break inside a cell
- [x] Backspace in an empty table (or with the whole table selected) deletes it as one undo step
- [x] Selecting across cells selects whole cells; copy, cut and delete act on those cells
- [x] View model exposes the grid for the UI; insta snapshots for a few tables
- [x] Rules added to PRODUCT_SPEC.md "Editor behaviour", each with a test
- [x] Tests added; `just check` passes; docs updated if structure changed

## Plan

New module `leaf-editor/src/table.rs` (+ tests); cells are text blocks (ADR 0061), so most editing already works.

- **View:** `BlockStyle::Table { header_row, rows, columns }` for the table's row and `BlockStyle::TableCell { row,
  column, header }` for each cell, listed right after the table in row-major order, one level deeper (row blocks
  aren't listed). The UI (E16-S03) builds the grid from these; `PageDoc::table_cells` gives it directly too.
- **Keys:** Tab / Shift+Tab go to the next / previous cell (caret at the end of its text); Tab in the last cell
  adds a row and goes to its first cell. Enter types a line break in a cell. Backspace at the start of a cell
  does nothing, unless every cell is empty: then the table goes (one undo step). Delete at the end of a cell does
  nothing. Left/Right already cross into the neighbouring cell (reading order).
- **Up/Down:** at a cell's first / last line, the cell above / below in the same column; past the top or bottom
  row, the block before / after the table. Coming into a table from above or below picks the column under the
  caret's x (the layout gives each cell's left edge).
- **Selection:** a text selection from one cell into another of the same table becomes `Selection::Cells { table,
  cells }`, the rectangle between them. Backspace/Delete/typing clear those cells (one step); copy gives one
  paragraph per cell (a table on the clipboard is E16-S04); marks apply to whole cells. A selection reaching from
  outside into a table takes the table whole.
- **Guards** so nothing tries to split, merge or convert a cell: slash menu and Markdown shortcuts don't open in
  cells; an image asked for in a cell goes after the table; pasting blocks into a cell joins their text with line
  breaks; block menu, drag and Tab over a selection act on the whole table; pasting a fragment that holds a table
  gives one paragraph per cell until E16-S04.
- **UI:** the highlight code learns `Selection::Cells` (whole cells); drawing tables is E16-S03.
- **Docs/tests:** PRODUCT_SPEC.md "Editor behaviour" rows for each rule, each with a test; insta snapshots of
  table view rows; ARCHITECTURE.md paragraph.
