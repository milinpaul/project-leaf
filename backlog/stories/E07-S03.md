## Context

Forward keys, IME and mouse events to leaf-editor.

## Acceptance criteria

- [x] IME works for at least Hindi, Japanese and emoji picker
- [x] Click places caret, drag selects, double/triple click word/block
- [x] Keystroke→paint under 16 ms on large page
- [x] Tests added; `just check` passes; docs updated if structure changed

## Plan

- Remove the per-block text inputs: every block is the rich text view; the page has its own focus and key context.
- `shell/page_keys.rs`: actions + bindings (Cmd on macOS, Ctrl elsewhere) calling `PageEditor`: structural keys,
  motions, Shift-extends, Up/Down via `PaintedLayout`, select all, formatting, undo/redo, copy/cut/paste (Markdown
  text + fragment metadata).
- `shell/ime.rs`: `EntityInputHandler` on the shell; the caret block with the draft spliced in, UTF-16 offsets;
  composing = `set_preedit`, commit = `commit_preedit`; draft drawn underlined.
- Mouse in `rich_text.rs`: click / shift-click / drag / double (word, new `select_word_at`) / triple (block).
- Performance: editor block order from the incremental view (was a full rebuild per keystroke).
- Tests: keys, shortcuts, clipboard, Japanese/Hindi/reconversion/abandon/empty-draft/emoji-picker/accent-menu
  sequences, UTF-16, mouse; editor tests for word/block select. Real-app check with real keystrokes; headless
  screenshots; `bench` typing timing. ADR 0040.
