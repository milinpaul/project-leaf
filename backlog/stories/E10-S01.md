## Context

Phase 1 adds `[[page links]]` with autocomplete and a backlinks panel (PRODUCT_SPEC.md, Phase 1). Before writing the
E10 stories, prove how a link to a page lives inside a block's Loro text: how it survives typing around it, merges
between two devices, undo, copy and paste, an older version of Leaf, and the target page being renamed, trashed or
deleted; and how backlinks are found fast in a 5,000-page workspace. Throwaway-quality tests only; no production
code.

## Acceptance criteria

- [x] Spike tests (Loro directly, no production code) show a page link stored in a block's text, with typing before
      and after it never growing or splitting it
- [x] Two-peer tests: a link deleted on one peer while the other formats or types around it, and the same link
      inserted twice, converge to a sensible result
- [x] An older peer that doesn't know the link mark edits the text and the link survives untouched
- [x] Undo of deleting a link brings back the same link to the same page
- [x] Measured: finding every link in a 5,000-page workspace, and a backlinks lookup (release build)
- [x] Proposed ADR with the model, findings and the open product questions for the owner
- [x] E10 stories written from the findings (status `backlog`)
- [x] Tests added; `just check` passes

## Plan

- `crates/leaf-model/tests/links_spike/` (test target, Loro directly): `main.rs` a page-link helper over LoroText
  (one placeholder character carrying a `page` mark whose value is the page ID) plus the typing, unknown-mark,
  undo and copy tests; `merges.rs` two-peer cases; `perf.rs` an ignored 5,000-page link scan and lookup in release.
- Compare with the alternative of the existing `link` mark over the title's text (stale titles, partial edits).
- Record the model, findings, measurements and open owner questions in ADR 0071 (Proposed).
- Write E10-S02.. as `backlog` stories; update the E10 epic notes.
