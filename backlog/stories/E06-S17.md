## Context

The owner wants a search field at the top of the sidebar, like Notion's: a rounded box under the workspace header
reading "Search" with the shortcut shown at its right (`⌘K` on macOS, `Ctrl+K` elsewhere). It is a doorway, not a
second search: clicking it opens the existing search bar (E11), exactly as the shortcut does. No "ask" (no AI or
network in Phase 0).

## Acceptance criteria

- [x] A full-width, rounded search field under the sidebar header with a search icon, "Search" placeholder and the platform's shortcut hint at the right, in Leaf's theme (light and dark)
- [x] Clicking it (or pressing Enter/Space when focused) opens the search bar, the same as `Cmd/Ctrl+K`; it never holds text itself
- [x] Hover state; tooltip-free (the hint says it all); from the keyboard, the shortcut it shows does the same
- [x] Hidden with the rest of the sidebar when the sidebar is collapsed
- [x] Window test that a click opens the search bar; screenshots in the PR, light and dark
- [x] Tests added; `just check` passes; docs updated if structure changed

## Plan

- New `leaf-ui/src/shell/sidebar_search.rs`: a 30 px rounded field (search icon, "Search", `Kbd` hint) between the
  sidebar header and "Pages"; a click (on release, so the search box keeps focus) calls `Shell::open_search`.
- The hint is built from `menus::SEARCH_KEYS`, a new constant the Cmd/Ctrl+K binding also uses, so they can't
  disagree. (gpui's binding lookup needs a previous frame and the app's bindings, so it missed the first frame.)
- Add the `Search` icon to Leaf's bundled icons.
- Window test in `search/tests.rs`: hint drawn; click opens; Escape closes; typing after a click finds a page.
- Docs: PRODUCT_SPEC search section, ARCHITECTURE search paragraph. No ADR (small UI addition, no new decision).
- Keyboard: the field isn't a Tab stop (nothing else in the sidebar is); the shortcut it shows is the keyboard way.
