## Context

Add a `table` block kind to `leaf-model`: a grid of cells, each holding rich text with the usual marks, plus an
optional header row. Commands change it like every other block, with undo, and two peers editing different cells
converge. Write the ADR choosing the shape (for example rows of cells as child blocks vs. one block holding a
grid) with merging and unknown-data preservation in mind.

## Acceptance criteria

- [x] `BlockKind::Table` with rows × columns of rich-text cells and a header-row flag; documented in BLOCK_MODEL.md
- [x] Commands: insert table (size), edit cell text and marks, add/remove row and column at a position, move row and column, toggle header row
- [x] Every command undoes and redoes exactly (proptest round-trip); two peers editing different cells converge (proptest)
- [x] A table from a newer version with data Leaf doesn't know keeps that data when saved
- [x] Saved and reopened through `leaf-store` unchanged
- [x] ADR written and added to the index
- [x] Tests added; `just check` passes; docs updated if structure changed

## Plan

**Shape (ADR):** a table is a block whose children are `table_row` blocks, whose children are `table_cell` blocks;
each cell holds a mergeable `text` like any text block. Cells get `BlockId`s, so the existing text and mark
commands, the caret (block + position), undo, merging, search indexing and saving all work on cells unchanged.
Columns are positions within rows (no column IDs): simple, and enough for Phase 0 (no sync yet).

- **Kinds** (`block_kind.rs`): `Table { header_row: bool }` (no text; children: rows only), `TableRow` (no text;
  children: cells only), `TableCell` (text with marks; no children). Generic `InsertBlock`/`SetBlockKind` can't
  create them (`check_creatable`), and `allows_children()` stays false for all three, so generic insert, move and
  indent can't put blocks into a table.
- **Commands** (`page_command.rs`, new `page_doc/table_ops.rs`): `InsertTable { parent, index, rows, columns,
  header_row }`, `InsertTableRow`/`DeleteTableRow`/`MoveTableRow { table, index | from, to }`, the same three for
  columns, and `BlockProp::TableHeaderRow(bool)` via `SetProp`. Cell text: the existing `InsertText`,
  `DeleteText`, `ReplaceText`, `SetMark`, `RemoveMark` on a cell's `BlockId`. At least one row and one column
  always (removing the last is refused). Read helper `PageDoc::table_cells(table) -> rows of cell ids`.
- **Guards:** structural commands naming a row or cell (delete, move, duplicate, indent, outdent, set kind, split,
  merge) are refused with a new `ModelError::TablePart`; whole tables can be deleted, moved and duplicated.
  Backspace into a table from the block below (`MergeIntoPrevious`) is refused with `MergeTargetNotText { table }`.
- **Invariants and repair:** invariant 3 generalised (tables hold only rows, rows only cells, cells nothing) plus
  a new 9: every row of a table has the same number of cells, at least one, and a table at least one row. Repair
  after a merge pads short rows with empty cells at the end (never drops a cell) and gives an emptied table one
  cell, outside undo.
- **Tests:** unit tests per command and guard; add table steps to the shared proptest generator so the existing
  invariant, undo round-trip and two-peer convergence properties cover tables; unknown data on table, row and
  cell survives edits and save/load; `leaf-store` save/reopen test.
- **Elsewhere:** the editor shows a table as a read-only placeholder until E16-S03 (view, block menu labels).
  Docs: BLOCK_MODEL.md (types, commands, invariants), ADR, ARCHITECTURE line.
