## Context

Add a `table` block kind to `leaf-model`: a grid of cells, each holding rich text with the usual marks, plus an
optional header row. Commands change it like every other block, with undo, and two peers editing different cells
converge. Write the ADR choosing the shape (for example rows of cells as child blocks vs. one block holding a
grid) with merging and unknown-data preservation in mind.

## Acceptance criteria

- [ ] `BlockKind::Table` with rows × columns of rich-text cells and a header-row flag; documented in BLOCK_MODEL.md
- [ ] Commands: insert table (size), edit cell text and marks, add/remove row and column at a position, move row and column, toggle header row
- [ ] Every command undoes and redoes exactly (proptest round-trip); two peers editing different cells converge (proptest)
- [ ] A table from a newer version with data Leaf doesn't know keeps that data when saved
- [ ] Saved and reopened through `leaf-store` unchanged
- [ ] ADR written and added to the index
- [ ] Tests added; `just check` passes; docs updated if structure changed
