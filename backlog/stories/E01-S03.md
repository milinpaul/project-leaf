## Acceptance criteria

- [x] CreatePage at parent+index returns PageId
- [x] RenamePage and SetPageIcon
- [x] Each command is exactly one Loro commit
- [x] Unit tests for each command
- [x] Tests added; `just check` passes; docs updated if structure changed

## Plan

- `leaf-model/src/command.rs`: `WorkspaceCommand` enum (`CreatePage`, `RenamePage`, `SetPageIcon`, more in
  E01-S04/S05) and `Outcome` (`PageCreated(PageId)` or `Changed`). `Workspace::apply` is the only write path.
- Each `apply` validates first, then writes, then calls `commit()` once, so a rejected command leaves no
  half-written changes and every command is one undo step later (E01-S06).
- `CreatePage { parent, index, title, created_at }`: the model mints the `PageId` and returns it. The caller
  supplies `created_at` (Unix ms): reading the clock panics on wasm32, and tests stay deterministic.
- `SetPageIcon { page, icon: Option<String> }`: `None` clears it. An empty string is rejected. Whether the text
  is a single emoji is left to the emoji picker, since the spec says only "optional emoji icon".
- New errors: index out of range, empty icon.
- Tests: each command, each error, rejected commands write nothing, one commit per command (counted with
  `subscribe_local_update`), reload after commands. Update BLOCK_MODEL.md's command list.
