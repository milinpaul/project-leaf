## Context

Search indexes row titles and text properties. Markdown export writes a database as a table (CSV as well). `leaf-bench` gets a 10,000-row database benchmark: open to first screen, full read, sort, filter, edit one cell, with budgets added to PRODUCT_SPEC.md for 10,000 rows (ADR-066 answer 5).

## Acceptance criteria

- [x] Rows and text properties are found by search
- [x] Benchmarks with budgets, run in CI on main
- [x] Tests added; `just check` passes

## Plan

Owner's answers (2026-11-01): database export moves to E12 (new story E12-S01); the budgets are open to first screen
< 100 ms, every row read < 1 s, a sort or filter change < 50 ms, editing one cell < 16 ms, for 10,000 rows.

- Search (`leaf-search`): rows are pages and already indexed by title; a test proves it. A database's text and URL
  cells are indexed as `property` entries under their row's page, so a hit opens the row. `PageSource` gains
  `database()` and `SavedVersions` the databases' versions; the index (version 6) records which version of each
  database it read and updates only the cells that changed. A row page's own re-index keeps its property entries.
  A property hit has no block to scroll to (`BlockHit::block` becomes optional).
- Benchmarks (`leaf-bench`): a 10,000-row database: open to first screen, read every row, sort, filter, edit one
  cell, each against its budget; run in CI on main with the other budget benches. Budgets added to PRODUCT_SPEC.
- Tests: index and sync tests (cells found, changed cell re-indexed, trashed row and database dropped, row page
  re-index keeps cells), search bar tests (no block to scroll to). ADR for indexing cells under row pages.
