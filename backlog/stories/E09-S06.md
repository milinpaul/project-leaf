## Context

A header menu per column and a `+` to add one: rename, change type (values convert on display, stored values kept until edited: ADR 0066 answer 3), move left or right or drag, hide, delete. Width by dragging the header edge.

## Acceptance criteria

- [x] Every column action works and is one undo step
- [x] Changing a column type keeps the stored values
- [x] Hidden columns can be shown again
- [x] Tests added; `just check` passes

## Plan

- `leaf-editor` `database_view/columns.rs`: column menu, add (named after the type), rename, retype, step left/right
  and dragged moves among shown columns, hide/show, width, delete; unit-tested with undo.
- Undo: `DatabaseEditor` makes each command its own step; `Database::group` (new, Loro undo groups) for actions of
  several commands (create option + pick).
- `leaf-ui`: header cells and "+" column (`header.rs`), menus (`column_menu.rs`), shell glue (`columns.rs`), table
  drag-to-move and drag-to-resize, Cmd/Ctrl+Z on a database page. `options.rs` split from `editing.rs` (was 402 lines).
- Window tests per action; screenshots light and dark; ADR 0072; ARCHITECTURE.
