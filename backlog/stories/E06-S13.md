## Context

The `main` CI runs after #59 (E06-S09) and #61 (E07-S03) went red on the full test matrix:

- **#59 (macOS and Windows):** the sidebar switcher test compared the opened folder's path with the
  path as written. The recent list stores resolved paths (on macOS `/var/…` resolves to `/private/var/…`). #61
  already fixed the test. The same mismatch remained in the app: the workspace menu could leave the open
  workspace unticked when Leaf was started with a folder path that goes through a link.
- **#61 (Linux and Windows):** the input-bridge tests pressed `cmd-b`, `cmd-z` and so on. Those are the
  shortcuts only on macOS; the app binds the platform's key (Ctrl elsewhere), so the tests failed off macOS.

## Acceptance criteria

- [x] The workspace menu ticks the open workspace however its path was written (test with a link)
- [x] The input-bridge tests press the platform's shortcut key (`secondary-…`), so they pass on all three systems
- [x] Tests added; `just check` passes

## Plan

- `sidebar.rs`: compare resolved paths (`same_folder`), with a unit test through a symlink.
- `shell/ime/tests.rs`: `cmd-x` → `secondary-x`.
