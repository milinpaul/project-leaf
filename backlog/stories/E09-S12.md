## Context

Found by the `database` proptest `history::undo_walks_back_through_every_state_and_redo_walks_forward` during
`just check` on the E10-S01 branch (2026-10-31); the failure is in `main` code, not the spike. Undo walks back to a
state whose select cell is empty (`Options({})`) where the recorded state held the option.

Proptest regression line (add it to `crates/leaf-model/tests/proptest-regressions/history.txt` as the failing test):

```
cc 04a45ecda60c16c5ba28441c6c33d3ed1c122112f4b3c9e90de87e6d86e3d9ad # shrinks to steps = [AddColumn(0, 164), AddRow(0), AddOption(0, 0), SetCell(0, 0, 1), SetColumnType(0, 191), ClearCell(0, 0), DeleteOption(0, 0), SetColumnType(0, 255), SetCell(0, 0, 0)]
```

## Acceptance criteria

- [x] The regression line is committed and fails before the fix
- [x] Undo and redo restore every recorded state for that sequence; the proptest passes
- [ ] `just check` passes

## Plan

- Cause: a multi-select cell's map is a *mergeable* container, so taking it out of the row (clearing the cell
  while the column was a select, or a plain value over it) and putting it back later gives the same container with
  its old options inside. The write that empties it then happens in a container undo/redo doesn't follow: undo of
  the clear brought the map back empty, and redo of the last write brought the old option back.
- Fix (`database/apply.rs`, `property.rs`): a cell that has a map keeps it. A plain value set over it goes inside
  under `=`; clearing empties the map; writing options removes `=`. Reading: in a non-multi-select column, `=` is
  the value, an empty map is no value, a map with options reads as before.
- Tests: the regression line (fails before the fix), deterministic tests for the clear path and the text path
  (fail before the fix), 10,000-case runs of the database proptests. ADR 0066 amended; BLOCK_MODEL updated.
