## Context

InsertText, DeleteText, SetMark, RemoveMark.

## Acceptance criteria

- [x] Unicode-safe offsets (tests with emoji and Indic scripts)
- [x] Marks follow the expand table in docs/architecture/BLOCK_MODEL.md
- [x] Code blocks reject marks
- [x] Link mark stores href
- [x] Tests added; `just check` passes; docs updated if structure changed

## Plan

Done with E02-S06 on one branch (owner request).
- `PageCommand::InsertText { id, pos, text }`, `DeleteText { id, range }`: positions are Unicode scalar offsets
  (BLOCK_MODEL.md), checked against the text length; the editor converts to graphemes (E04). Empty insert or
  empty range: `Unchanged`. Blocks without text (dividers, unknown) are rejected.
- `SetMark { id, range, mark: Mark }` / `RemoveMark { id, range, kind: MarkKind }`: `Mark` = bold, italic,
  strike, code, `Link(href)`; expand rules come from the configured table. Code blocks reject marks; empty
  link href is rejected. New errors: `TextOutOfRange`, `MarksNotAllowed`, `EmptyLink`.
- Tests: emoji with skin tone and Devanagari conjuncts at every offset; expand behaviour per mark; code block
  rejection; link href read back. A proptest compares random inserts/deletes of mixed scripts against a
  `Vec<char>` reference.
