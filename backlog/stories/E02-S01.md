## Context

Page LoroDoc with 'blocks' tree, text style config and BlockKind enum read/write.

## Acceptance criteria

- [x] BlockKind enum matches docs/architecture/BLOCK_MODEL.md
- [x] Text styles configured on doc creation and load
- [x] Read API: root blocks, children, block kind, text with marks
- [x] Unknown types surface as BlockKind::Unknown and are preserved
- [x] Tests added; `just check` passes; docs updated if structure changed

## Plan

Done with E02-S02 on one branch (owner request).
- `leaf-model/src/block_kind.rs`: `BlockKind` exactly as BLOCK_MODEL.md, plus `Unknown { type_name }`. Read from a
  block's `type` plus `props`; known types with bad props (heading level 7) are an error, never guessed.
  `allows_children()` and `has_text()` encode the table.
- `leaf-model/src/text.rs`: the mark table as `config_text_style`, applied on create and on load; `TextSpan
  { text, marks }` with `Marks { bold, italic, strike, code, link }` read from Loro's delta.
- `leaf-model/src/page_doc.rs`: `PageDoc` owns a page's `LoroDoc` and `"blocks"` tree, and a `BlockId ↔ TreeID`
  index (ADR 0006 pattern). `new`, `from_bytes` (strict about block ids), `to_bytes`, `root_blocks`,
  `children`, `kind`, `text`.
- Unknown types: read as `Unknown`, their meta is never rewritten. They can't take new children.
- Tests: every kind round-trips through save/load, bad props, unknown types preserved byte for byte, marks read
  back with the configured expand behaviour, bad block ids rejected on load.
