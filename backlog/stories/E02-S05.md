## Context

SplitBlock (Enter) and MergeIntoPrevious (Backspace) model semantics.

## Acceptance criteria

- [x] Split keeps marks on both halves
- [x] Split type rules per PRODUCT_SPEC Editor behaviour
- [x] Merge appends text and moves children to the previous block
- [x] Merge onto divider/image is rejected with a typed error the editor can handle
- [x] Tests added; `just check` passes; docs updated if structure changed

## Plan

New module `page_doc/split_merge.rs`.
- **`SplitBlock { id, pos }`** (Enter mid-text) returns `BlockCreated(new)`. The text after `pos` moves to the
  new block **with its marks** (`slice_delta` then `apply_delta`, so marks from newer versions survive too).
  - New kind per the spec: lists and to-dos continue (an unticked to-do); everything else becomes a paragraph.
  - Placement: right after the block, or as its **first child** if it has children, so reading order never changes.
  - Blocks without text are refused.
- **`MergeIntoPrevious { id }`** (Backspace at start) appends the block's text, with marks, to the previous
  block **in reading order**, then deletes it. It returns `BlockMerged { into, at }` so the editor can put the
  cursor at the join.
  - Children move to the previous block: at the block's old position if the previous block is its parent,
    otherwise at the end. If the previous block can't hold children (heading, code), they move up to the
    block's own position instead.
  - Merging into code strips marks (invariant 5). With no previous block: `Unchanged`.
- **Refused:** merging into a divider, image or unknown block gives a typed `MergeTargetNotText { target }`, so
  the editor can select that block instead (spec).
- **Interim editor:** Enter splits at the input's cursor; Backspace at the start of a non-paragraph turns it into
  a paragraph; at the start of a paragraph it merges into the block above, landing the cursor at the join.
- **Tests:** each rule plus mark preservation on both sides; extend the block-text proptest with split/merge
  against a reference.
