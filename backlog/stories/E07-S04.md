## Context

Hover ⋮⋮ handle with the block actions menu.

## Acceptance criteria

- [x] Appears on hover, keyboard accessible
- [x] Menu triggers block actions
- [x] Menu has Move up and Move down (owner request, 2026-10-29)
- [x] Every menu item has an icon (owner request, 2026-10-29)
- [x] Tests added; `just check` passes; docs updated if structure changed

## Plan

- **Editor (`leaf-editor`):** `BlockAction::MoveUp` / `MoveDown` move the action's blocks one place among their
  siblings with the existing `MoveBlocks` command (one undo step); disabled at the edge or when the blocks have
  different parents. New `block_menu.rs` keeps the open menu like the slash menu: which block, the highlighted
  entry, and a "Turn into" submenu. Keys (Up/Down/Left/Right/Enter/Escape) and clicks go through it, so it is
  testable without a window.
- **UI (`leaf-ui`):** a ⋮⋮ grip in the left gutter of each row, shown on hover; clicking it opens the menu.
  `Cmd/Ctrl+/` opens it for the caret's block (keyboard access). The menu draws icons (Lucide) per entry, has its
  own focus and key context, and closes on a click outside.
- **Tests:** editor tests for moves (edges, nesting, selection, undo) and menu navigation; a window test for the
  handle and Cmd+/; screenshot of the open menu.
- **Docs:** PRODUCT_SPEC block handle line, ADR, ARCHITECTURE paragraph.
- **Risk:** row gutter clipping in the virtual list.
