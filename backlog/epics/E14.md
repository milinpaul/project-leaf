## Goal

Phase 3. The full Leaf editor in a web browser, kept in sync with the desktop app through a Leaf sync server.

## Notes

Direction agreed with the owner (2026-10-29), updated 2026-10-31 after the spike (E14-S01): see "Web app first" below.

- **Sync server:** Rust (`axum`, `tokio`), storing documents in **Postgres** and images in S3, as listed in
  TECH_STACK.md. Devices exchange small Loro updates; the server stores and relays them.
- **Store Loro data, not one row per block:** Postgres keeps each page as a Loro snapshot plus updates (the shape
  `leaf-store` uses in SQLite), with ordinary tables for users, workspaces and permissions. Per-block rows would
  break CRDT merging and drop unknown data (rule 5). Server-side search can be a Postgres full-text table filled
  from the documents.
- **Desktop keeps SQLite** and stays offline-first; Postgres is the shared cloud copy, not a replacement.
- **One storage interface** in Rust for both SQLite (desktop) and Postgres (server), so save/load logic is not
  written twice.
- **Browser editor:** the Rust core in WebAssembly plus the E13 rendering layer, a hidden text input for typing
  and input methods (no `contenteditable`), `leaf-editor` owning caret and selection.
- **Trade-off accepted:** the web editor needs a connection to open a workspace; an offline browser copy may come
  later.
- Needs an ADR for the sync protocol and server storage before the first story starts.

### Web app first (owner, 2026-10-31)

The spike (E14-S01, `docs/spikes/E14-S01-web-editor.md`) showed `leaf-editor` and `leaf-model` editing a page in a
browser unchanged. The owner chose to build an independent web app around that WebAssembly build first, like Notion
on the web, with accounts and sync later:

- **Next.js (TypeScript)** draws the app (sidebar, page tree, menus, pages); the Rust core in WebAssembly owns every
  editing rule, as on desktop. Editor routes render in the browser only; server rendering is for a landing page and,
  later, shared pages.
- **Pages live in the browser first** (IndexedDB), stored as a Loro snapshot plus updates per page, the shape
  `leaf-store` uses in SQLite, so the later sync server uploads exactly what is stored. Export and import of a
  workspace file guard against cleared browser data.
- **Accounts and sync come later** through the Rust sync server above; the "needs a connection" trade-off no longer
  applies to the first version.
- This replaces "the E13 viewer first": E13's rendering work is folded into this app.
- Open: when it starts. E14 stays in Phase 3 until the owner moves it.

Order: S02 ADR → S03 `leaf-web` bindings → S04 Next.js app skeleton; then the browser layer from the spike report
(caret and selection, input methods, menus, images, search, export and import).
