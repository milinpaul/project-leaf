## Goal

Phase 3. The full Leaf editor in a web browser, kept in sync with the desktop app through a Leaf sync server.

## Notes

Direction agreed with the owner (2026-10-29); stories to be written when the read-only viewer (E13) is done.

- **Sync server:** Rust (`axum`, `tokio`), storing documents in **Postgres** and images in S3, as listed in
  TECH_STACK.md. Devices exchange small Loro updates; the server stores and relays them.
- **Store Loro data, not one row per block:** Postgres keeps each page as a Loro snapshot plus updates (the shape
  `leaf-store` uses in SQLite), with ordinary tables for users, workspaces and permissions. Per-block rows would
  break CRDT merging and drop unknown data (rule 5). Server-side search can be a Postgres full-text table filled
  from the documents.
- **Desktop keeps SQLite** and stays offline-first; Postgres is the shared cloud copy, not a replacement.
- **One storage interface** in Rust for both SQLite (desktop) and Postgres (server), so save/load logic is not
  written twice.
- **Browser editor:** the Rust core in WebAssembly plus the E13 rendering layer, a hidden text input for typing
  and input methods (no `contenteditable`), `leaf-editor` owning caret and selection.
- **Trade-off accepted:** the web editor needs a connection to open a workspace; an offline browser copy may come
  later.
- Needs an ADR for the sync protocol and server storage before the first story starts.
