## Goal

Phase 1. Paste a web address and choose to show it as a **web bookmark**: a card with the page's title, description,
site icon and preview image, like Notion's bookmark block.
The owner named it "web bookmark" (2026-10-31) so it is never confused with a text link or a page link (E10). The spec's non-goals already say "show link preview
cards instead" of live web embeds; this is that card.

## Notes

Agreed with the owner (2026-10-29):

- **Order:** after the database table view (E09), which makes collecting links more useful (reading lists,
  research). Bookmarks don't depend on E09 technically; a database URL column can reuse the preview fetcher later.
- **Network is opt-in.** Fetching a preview is Leaf's first network access, from the owner's own computer, so the
  linked site sees their IP address. A setting turns it on (off by default, asked once); with it off Leaf never
  touches the network and bookmarks show the address and domain only.
- **Fetch safely:** `http`/`https` only, short timeouts, size limits, no local-network addresses, no JavaScript;
  only the title, description, preview image and icon are read.
- **Works offline after fetching:** the title, description and images are saved in the page (images as assets), so
  cards show without a connection and will sync later.
- **Not in scope:** inline link mentions with titles, and live embeds (no webview, principle 1).

Decided in ADR-XXX-E15-S01 (the E15-S01 spike): stored as `web_bookmark`; the fetcher is a new native crate
`leaf-fetch` on `ureq` + `html5ever`'s tokenizer, with the address check inside the DNS resolver.

Order: S01 ADR → S02 block → S03 paste and convert, S05 fetcher (in parallel) → S04 card UI → S06 setting →
S07 export.
